> **这是什么**：显存池管理器的分层存储子系统（`flagmemory.tiering`）的组件设计文档——定义三级结构、一块内容该放哪一级的决策规则、换出与换入的触发条件、与已完成的 KV 卸载资产的衔接关系、分层存储自己新增的那几条对外接口，以及本子系统的不变量。

> - 决策记录 ADR-0013《显存池管理器交付形态定形》（登记处 = 指挥台仓 `decisions/`；一句话：18 条交付条目的产物口径 = 可被别人 import / 链接调用的源代码 + 接口头文件与接口文档 + 单测与实测证据，报告是证据不是交付物本体）。其第 3 节第 5 条第三项即本文件的出口判据：**三级放置决策规则 / 换入换出触发条件 / 与已完成的 KV 卸载结论的衔接**。

## 当前实现边界

当前查询中的 `pool_in_use`、`pool_reusable`、`pool_pending`、`pool_quarantined` 来自本组件显式接管块的账本；文中沿用的「引擎侧」在当前实现里仅指这组池内统计，不是已接入 vLLM 的全局 KV 指标，也不表示自动接管框架全部分配。设备侧三键来自后端设备查询，范围与本池账本不同；历史 vLLM 画像是设计输入，不能充抵当前组件的运行覆盖。`engine_fragmentation` 当前为本池可复用字节除以本池持有字节，非全局引擎碎片率。

本文件的通用分层管理器、放置决策、换入换出接口及池回调属于后续设计；现有三套框架卸载适配器不等于此管理器已实现。当前 `create_pool` 没有换出回调参数，`reclaim(allow_tier_offload=True)` 明确抛 `NotWired`，不返回假成功。池的实际租约访问、关闭托管和测试边界见 [实现说明](../impl/11-28-分级块池与流有序分配.md)。接口语言面仍 **Proposed**。

SDK 原语事实以指挥台仓 `inbox/调研-四芯片SDK显存原语面补探-20261103.md` 为指针：四家跨进程共享句柄已有头文件/符号调查；虚址映射、流有序分配和粒度存在各家/现场能力差异。SDK 调查不等于统一后端已声明、更不等于池/跨进程路径已运行验证；平头哥池设备属性实际值、昆仑芯粒度基数及生命周期运行语义仍未收口。当前基线仍自管张量路径，不承诺原生优化。

## 一、三级结构

### 1.1 三级各是谁

| 级 | 介质 | 持有者 | 它放什么 | 搬运方向 | 现状 |
|---|---|---|---|---|---|
| **第一级 · 设备显存** | 芯片显存 | **池本体**（`flagmemory.pool`） | 全部用途标签的块：权重 / KV 缓存 / 激活 / 通信缓冲 / 临时工作区 / 未声明 | — | 池本体已定义（《显存池概念与设计基础》第一至四节） |
| **第二级 · 主机内存** | 主机侧内存（锁页优先，不可锁页则退普通页） | **分层存储的搬运适配层** | 只放可下放的内容，现状只有 KV 缓存 | 级一 ⇄ 级二 | 三家各有一套已实测闭环的搬运适配层（第四节）；寒武纪 MLU590 没有 |
| **第三级 · 更慢介质** | 本机持久介质或远端存储 | 未实现 | 预留给冷 KV 条目与跨请求长期前缀 | 级二 ⇄ 级三 | **结构留位，本文件只定接口与决策位置，不承诺实现**（第八节第 2 条） |

三级的分工用一句话说清：**池本体管级一的块，分层存储管级一到级二（将来到级三）的内容搬运与放置决策**。分层存储**不接管**级一的分配与回收——它向池要块、向池还块，走的是池的 `alloc_on_stream` 与 `free_block`，不另开一条分配路径。

### 1.2 分层存储与池是什么关系

**答：分层存储是池的上层消费方，不是池的内部模块；它单向依赖池。**

《显存池概念与设计基础》第 1.4 小节已把「分层存储与 KV 卸载适配层」列为池的调用方（「向池要块、按池的水位决定换入换出」）。本文件把这条关系收紧为三句话：

| # | 关系 | 含义 |
|---|---|---|
| 1 | 分层存储 → 池：**单向依赖** | 分层存储调用池的公开接口（第六节第 2 小节逐条列），不读池的内部数据结构，不绕过池直接向底座取块 |
| 2 | 池 → 分层存储：**只经一个回调口，不反向 import** | 后续设计的压力回收触发拟走建池时登记的换出回调；当前无该参数，`allow_tier_offload=True` 抛 `NotWired`。池本体**不 import 分层存储，更不 import 任何推理框架**（不变量 `T-5`） |
| 3 | 搬运适配层 → 推理框架：**允许，且只在这一层允许** | 框架绑定下沉到搬运适配层（依据 ADR-0014 第 3.5 节第 4 条「解栈耦合」）。适配层经推理引擎的 KV 外挂点加载，池本体与分层存储管理器本体都不碰框架 |

## 二、三级放置决策规则

### 2.1 五条判据与各自的取数口径

放置决策只许用下表五类判据。**每条判据必须说清数从哪一层来**——这是不变量 `T-1`（双指标）能被检验的前提。

| # | 判据 | 取数口径（具体读什么） | 数来自哪一层 | 取不到时 |
|---|---|---|---|---|
| 1 | **用途标签** | 块账目里的用途标签字段（六类枚举：权重 / KV 缓存 / 激活 / 通信缓冲 / 临时工作区 / 未声明），由申请方填在内存句柄上 | **池**（账目字段，枚举定义见《显存池概念与设计基础》第 4.3 小节；该小节是 11-25 与设备执行上下文方向联合冻结的池侧口径） | 按「未声明」处理 ⇒ 永不下放（`T-3`） |
| 2 | **当前水位（双指标）** | ① **设备侧**：总量 / 已用 / 空闲三键（`L0` 四家齐备能力）；② **引擎侧**：池内已分配 / 可复用 / 待回收 / 隔离 | **池** 的 `query_watermark`，两侧同时返回（池的 `I-6`） | 设备侧不可用 → **报错不启分层存储**，不用引擎侧单边数充抵（池的 `I-6` + 本文件 `T-1`） |
| 3 | **预算余量与负载类型** | 按用途标签聚合的已分配量 + 当前负载类型下的可压余量判读（向量化 = 纯余量 / 生成式 = 真实并发容量 / 混合） | **池** 的 `query_budget`；负载类型是池创建时的入参（池的 `I-7`） | 聚合口不可用 → 用池自统计并标明来源；负载类型未给 → 按「生成式」最保守处理（不压并发容量） |
| 4 | **访问频度** | 该条目在最近一个统计窗口内被命中的次数（命中 / 未命中分别计） | **搬运适配层**（引擎侧条目索引；设备侧读数看不见条目级访问，见 `T-1` 的理由） | 退化为「只用判据 1 + 2 + 5」并上报降级态，不静默把频度当 0 |
| 5 | **重用距离** | 该条目最后一次被访问时的全局访问序号与当前序号之差（按条目计，不按字节计） | **搬运适配层** | 同上 |

> 判据 2 的双指标口径是本节的地基：**预分配会让设备侧显存读数恒平**（实例：某次实测中设备侧波动仅 142 MiB），条目的真实涨落只在引擎侧指标里可见。只看设备侧会把一个正在剧烈换入换出的系统读成「没有动态」。

### 2.2 放置决策表

读法：**从上往下第一条命中的规则生效**（规则有序，先判永不下放，再判水位，最后判冷热）。「水位区间」按双指标判读：`高` = 设备侧与引擎侧**同时**越过高水位阈值；`低` = 两侧**同时**在低水位阈值以下；其余为 `中`。阈值定义与归属见第三节第 2 小节。

| # | 用途标签 | 访问频度 | 重用距离 | 水位区间 | 负载类型 | **放置** | 依据 |
|---|---|---|---|---|---|---|---|
| R1 | **权重** | 任意 | 任意 | 任意 | 任意 | **级一，永不下放** | 池的 `I-12`（权重与通信缓冲永不被池回收或复用，只记账）；本文件 `T-3` |
| R2 | **通信缓冲** | 任意 | 任意 | 任意 | 任意 | **级一，永不下放** | 同上。该标签的块由通信方向申请，分层存储动它会与通信方向打架 |
| R3 | **未声明** | 任意 | 任意 | 任意 | 任意 | **级一，永不下放** | 池的 `I-12` 的最保守处理（不回收、不复用）在本层等价于不下放；`T-3` |
| R4 | **临时工作区** | 任意 | 任意 | 任意 | 任意 | **级一，不下放**（由池最优先回收，不进分层） | 算子工作空间生命周期短于一次搬运往返，下放是净亏；池的复用优先级已把它列为最优先回收 |
| R5 | **激活** | 任意 | 任意 | 任意 | 任意 | **级一，不下放**（由池复用） | 激活是池**块复用**的主战场（《显存池概念与设计基础》第 3.2 小节），其生命周期短于搬运往返 |
| R6 | KV 缓存 | 任意 | 任意 | 任意 | 任意 | **分层存储未启用 / 本后端无搬运适配层 ⇒ 级一，不下放** | `T-11`：无适配层时显式不可用，不静默伪装可用（寒武纪 MLU590 现状，第四节第 4 小节） |
| R7 | KV 缓存 | 任意 | 任意 | **高** | 任意 | **换出到级二**（按 R9/R10 的候选排序挑） | 第三节第 1 小节换出触发 E1 |
| R8 | KV 缓存 | 任意 | 任意 | 中 / 低 | 任意 | **留级一** | 水位未到，搬运是净成本 |
| R9 | KV 缓存 | **低** | **远** | 高 | 任意 | **优先换出（候选序最前）** | 冷且久未用，换出代价最低 |
| R10 | KV 缓存 | **高** | **近** | 高 | 任意 | **最后才换出**（同批候选中序最后） | 热条目换出后极可能立刻被召回，正是抖动的来源（`T-2`） |
| R11 | KV 缓存 | 高 | 近 | 高 | **向量化** | **留级一，改为先压第二层预分配余量** | 池的 `I-7`：向量化负载的池是**纯余量**，压它不掉并发；此时压余量优于搬运 |
| R12 | KV 缓存 | 高 | 近 | 高 | **生成式** | **按 R9→R10 序换出，不压预分配** | 池的 `I-7`：生成式负载的池是**真实并发容量**，压了直接掉并发 |
| R13 | 级二的 KV 条目 | 任意 | 任意 | 级二高水位 | 任意 | **换出到级三；级三未实现 ⇒ 按级二淘汰策略丢弃并计入审计** | 第八节第 2 条（级三留位） |
| R14 | 级二的 KV 条目 | — | — | 引擎侧报命中 | 任意 | **换入到级一** | 第三节第 2 小节换入触发 I1 |

**永不下放清单（R1–R5 的汇总，`T-3` 的正文）**：**权重、通信缓冲、用途标签为「未声明」的块，永不下放**；**临时工作区与激活不进分层**（原因不同——前三类是安全约束，后两类是成本判断，但对外行为一致：分层存储不搬它们）。

> 对照关系写明：R1–R3 是**池的不变量 `I-12`**（登记处 = 本仓 `docs/design/显存池概念与设计基础.md` 第三节第 5 小节；一句话：权重与通信缓冲永不被池回收或复用，只记账，未声明标签按最保守处理）在分层存储这一层的等价表述，**不是一条新约束**。本文件 `T-3` 只负责把它在搬运路径上再钉一次，编号空间不同、语义同源。

### 2.3 决策的产出形态

放置决策**只产出判定，不产出动作**。`classify_placement`（第六节第 1 小节）返回三样：目标级别、命中的规则号（R1…R14）、以及该次判定用到的五条判据读数（含双指标两侧的数）。搬运动作由 `evict` / `promote` 另行发起。

这样分家的理由有两条：① 调度与监控方向可以**只查判定不触发搬运**；② 判定的依据可被逐条复核——一次换出若事后看是错的，能查出是哪条判据的读数不对，而不是只能看到「换出了」。

## 三、换入换出触发条件

### 3.1 触发条件表

换出 = 级一 → 级二（设备显存 → 主机内存）；换入 = 级二 → 级一。**一切触发判据都是双指标**（`T-1`）：凡出现「水位」二字，都指设备侧与引擎侧两侧的读数，且必须同时满足。

| # | 方向 | 触发条件（全部满足才触发） | 判据阈值 | 不触发时 |
|---|---|---|---|---|
| **E1** | 换出 | ① **设备侧**占用 ≥ `H_dev`；② **引擎侧**占用 ≥ `H_eng`（等价说法：池内「可复用 + 待回收」余量已低于 `1 − H_eng`）；③ 存在按 R7–R12 可换出的候选；④ 级二剩余容量 ≥ 一次搬运粒度；⑤ 候选不在最小驻留窗口内（`T-2`） | `H_dev` / `H_eng` 可配置，默认由能力层推导（3.2） | 不换出；若因条件③或④不成立而不换出，**显式返回原因**，不报成功（`T-4`） |
| **E2** | 换出 | 池的压力回收（`reclaim`）明确要求「允许触发分层换出」，并给出目标释放量或压力等级 | 目标量由调用方给 | 如实返回实际换出量并标「未达目标」，不谎报（池的 `I-10`、本文件 `T-4`） |
| **E3** | 换出 | 下一次 `alloc_on_stream` 因容量不足报错，且错误里的双指标水位与该档空闲量显示换出可解 | 由调用方按报错重试，**池不自动触发** | 池绝不为满足一次请求静默换出（池的 `I-10`：不自动缩小请求、不自动换档） |
| **E4** | 换出 | 级二水位到高位，向级三换出 | 级三未实现 ⇒ 按 R13 处置 | 计入审计的「级三缺失丢弃」计数 |
| **I1** | 换入 | ① 引擎侧报该条目**未命中级一但命中级二**（条目索引查到）；② 池能分出一块（`alloc_on_stream` 成功）；③ 该条目不在冷却窗口内，**或**本次是真实请求召回（3.3 第 2 条） | — | `alloc_on_stream` 报容量不足 ⇒ **换入失败，向上报错**；**不许静默当作未命中**（`T-4`） |
| **I2** | 换入 | 预取：引擎侧给出将要用到的条目清单，且设备侧与引擎侧占用**同时**在低水位阈值 `L_dev` / `L_eng` 以下 | `L_dev` / `L_eng` 可配置，且必须满足滞回带约束 `L ≤ H − 一次搬运粒度 × N`（`T-2`） | 不预取。预取**永不**挤占真实请求的换入额度 |
| **I3** | 换入 | 调用方显式要求把某条目拉回级一（运维或测试路径） | — | 失败即报错，不降级 |

> E1 条件②的写法值得多说一句：**只看设备侧空闲永远是错的**。第二层的预分配一次吃满空闲显存后，设备侧空闲在整个服务生命周期里几乎是一个常数（实例：某次实测中设备侧波动仅 142 MiB）。把它当换出触发的唯一判据，结果是**要么一次都不触发，要么一直触发**。引擎侧的（可复用 + 待回收）才是池里真正的余量。

### 3.2 阈值由谁定：取舍

三条路，取中间那条。

| 方案 | 取舍 | 理由 |
|---|---|---|
| 固定常数（编译期写死） | ✗ 不采用 | 底座块粒度在四家上不同（实例：平头哥 PPU 那栈默认块大小为 512 KB/块），池容量与单 token 的 KV 成本也随模型变。写死常数等于在三家上调不动，且与池的「档位粒度不写死常数」直接冲突（`T-9`） |
| **可配置 + 默认值由能力层推导（现行方案）** | ✓ **采用** | 阈值全部是**运行期可配置项**（`set_tier_policy`），不给则由能力层按三件事推导默认值：① 后端的分配粒度（池能力层已有）；② 搬运适配层声明的一次搬运粒度（某栈的块大小，实例：平头哥那栈是 512 KB/块）；③ 池容量与单 token 的 KV 成本（实例：0.14 MiB，单卡口径）换算出的条目数。推导出的实际生效值**必须可查**（`query_tier_capability` 返回） |
| 自适应（按运行时反馈自动调开闸阈值） | △ **限定采用** | **只允许作用在候选排序上，不允许作用在开闸阈值上。** 排序错了只是换出了不该先换的那块，代价有界且可审计；开闸阈值自适应则会让「为什么这一刻换出了」变成不可复现的问题，并与抖动抑制的滞回带互相打架 |

### 3.3 抖动抑制

抖动 = 刚换出的条目立刻被换回，或刚换入的条目立刻被换出。四条机制，全部**可查、可配、默认开**（`T-2`）。

| # | 机制 | 做法 | 为什么 |
|---|---|---|---|
| 1 | **滞回带** | 换出的高水位阈值与换入预取的低水位阈值分开，且约束 `L ≤ H − 一次搬运粒度 × N`（`N` 可配，默认 ≥ 1）。单阈值一律视为缺陷 | 单阈值在阈值附近必然来回跳闸 |
| 2 | **冷却窗口** | 刚换出的条目在冷却窗口内**不作为预取（I2）候选**；但**真实请求召回（I1）不受冷却限制** | 冷却不能挡住正确性路径。挡住了就是「数据在级二却说未命中」，属静默退化（`T-4`） |
| 3 | **最小驻留** | 刚换入的条目在最小驻留窗口内不作为换出候选（E1 条件⑤）；`reclaim` 的强制换出（E2）可越过此窗，但要计入审计的「越窗换出」计数 | 没有最小驻留，一次换入的搬运成本会被下一刻的换出立刻抹掉 |
| 4 | **搬运预算闸 + 空转退避** | 单位时间的搬运字节数有上限（可配）；连续 `M` 次触发判读都挑不出候选则按指数退避拉长判读间隔，有候选时立即复位 | 搬运占用拷贝带宽与一条流；不设闸时抖动会把带宽吃光而对外看起来「只是慢」 |

四条机制的触发次数、冷却窗内被拒的预取次数、越窗换出次数，一律进 `query_tier_audit`。**抖动抑制生效本身必须是可观测的**——否则「为什么没换出」答不出来。

### 3.4 与池的回收屏障怎么衔接

这是本节最容易写错的一段：搬运是**流上的异步操作**，而池的块回收有自己的流序屏障。两者不衔接的后果是池把一块还在被 D2H 拷贝读取的显存判成可复用，交给下一个人——踩内存，且现象随机。

**换出（级一 → 级二）六步，顺序不可换：**

| 步 | 动作 | 约束 |
|---|---|---|
| 1 | 搬运流经池的 `register_stream` 登记 | 池对该流**强持有**到池销毁（池的 `I-3`：流 + 弱引用 + 被回收 = 进程退出期段错误，平头哥 PPU 与昇腾 910C 两家中招）。分层存储**不得**自己持有流做弱引用清理 |
| 2 | 块由计算流分配而搬运在另一条流 ⇒ 先 `declare_cross_stream_use`，把搬运流并入该块的跨流借用集 | 未声明就跨流搬运属**调用方错误**。池不承诺保护未声明的跨流读写（《显存池概念与设计基础》第 2.4 小节）。声明口在三家上经统一层的跨流内存保护能力（`L1`）落地，寒武纪 MLU590 上走池的降级路径（逐流取事件凭据） |
| 3 | 在搬运流上发起 D2H 逐块拷贝 | 一次搬运粒度由适配层按后端块大小声明，**不写死常数**（`T-9`） |
| 4 | 搬运完成确认**经统一后端接口的事件适配器** | **不许裸调厂商事件查询**（池的 `I-2`）：寒武纪 MLU590 与平头哥 PPU 上，没有 record 过的事件查询原生返回「已完成」——裸调会把一块还在拷贝的显存判成搬完 |
| 5 | 条目**先**落级二账本（主机侧块表 + 条目索引），**后**调池的 `free_block` | 顺序反了就有一个窗口：块已进池的待回收队列，而条目在级二还查不到 ⇒ 这期间的请求会被判成彻底未命中。**账本先行是正确性要求，不是优化** |
| 6 | 块进 `待回收`，池的屏障等**所属流 + 跨流借用集里所有流**确认完成后转 `可复用`；由 `drain_stream` 推进 | 屏障**只许超时 + 轮询，不许阻塞等待**，且**超时不等于失败**，按可恢复态上报（池的 `I-11`；四家里只有昇腾 910C 是真有界同步，其余三家的「有界」= 超时上报，含一家是轮询实现）。等待到期不按次数隔离，池以共同截止时间保留待回收资源 |

**换入（级二 → 级一）五步：**

| 步 | 动作 | 约束 |
|---|---|---|
| 1 | 向池 `alloc_on_stream` 要块，用途标签 = KV 缓存，绑定目标流 | 容量不足 ⇒ 池**报错**（错误里带双指标水位与该档空闲量）。分层存储**向上报错或显式降级，不许把它当成「未命中」**（`T-4`） |
| 2 | 跨流则先 `declare_cross_stream_use` | 同换出第 2 步 |
| 3 | 在搬运流上发起 H2D 逐块拷贝 | 同换出第 3 步 |
| 4 | 完成确认经事件适配器 | 同换出第 4 步（池的 `I-2`） |
| 5 | **确认完成后**才把块交调用方；级二的条目按策略保留或释放 | 未确认完成就交出去 = 交出一块内容不全的显存。保留级二副本可省下次换出的搬运，是否保留属可配策略，不属本文件冻结范围 |

### 3.5 失败行为

总纪律与池一致：**报错，或显式降级并上报降级态，二者之一；不静默退化**（池的 `I-10`，本文件 `T-4`）。

| 失败点 | 行为 | 禁止 |
|---|---|---|
| 换入时池容量不足 | 向上报错，附池返回的双指标水位 | 静默当作未命中；静默改小换入量 |
| 换出时级二容量不足 | 返回实际换出量并标「未达目标」 | 把部分成功报成成功 |
| 搬运过程报错（拷贝失败 / 适配层异常） | 换出：条目**不**落级二账本、**不**调 `free_block`，块留 `在用`，向上报错；换入：归还已分的块，向上报错 | 让块进 `待回收` 而条目两级都查不到（会丢数据） |
| 屏障超时 | 按**可恢复态**上报，块留 `待回收`，不阻塞；零等待只观察；正等待到期可恢复，不按次数隔离 | 把超时当失败；阻塞等待（池的 `I-11`） |
| 主机侧锁页不可用 | 退普通页并**显式上报降级态**（`query_tier_capability` 可查），正确性不受影响、带宽下降 | 静默降级 |
| 后端缺批量搬运原语 | 退逐块拷贝并**显式上报降级态** | 静默降级 |
| 该后端无搬运适配层 | `query_tier_capability` 报**不可用**及原因；换入换出调用一律报错 | 伪装可用后每次返回未命中（`T-11`） |
| 级二账本与级一块账对不上 | 立刻停止搬运并上报，相关块交池按归属校验处置（池的 `I-1`：拦截由池自己的账本完成，**不依赖厂商报错**） | 继续搬运；依赖厂商报错发现 |
| 设备级故障 | **只上报，不自救** | 任何设备重建路径（池的 `I-5`：四家里只有昇腾 910C 有设备级真重建，另三家分别是无原语、确认不具备、以及原语返回成功但设备随后全废） |

## 四、与已完成的 KV 卸载结论的衔接

### 4.1 三套搬运适配层在新结构里的位置

现有三套 KV→Host 卸载 connector（登记处 = 本仓 `flagmemory/tiering/offload/`）是**已实测闭环的资产**，在本设计里的位置是：**级一 ⇄ 级二 的搬运适配层实现，框架绑定、可选、每后端一套**。它们**不是**池本体，也**不是**分层存储管理器本体。

| 后端 | 适配层 | 加载方式 | 实测状态（登记处 = 本仓 `flagmemory/tiering/offload/README.md`） |
|---|---|---|---|
| 昇腾 910C | `flagmemory.tiering.offload.npu` | 经推理引擎的 KV 外挂点加载，**不改任何栈代码** | 最小闭环 + 开关对照 |
| 昆仑芯 P800 | `flagmemory.tiering.offload.xpu` | 同上 | 四步闭环；真模型 A/B 待补 |
| 平头哥 PPU | `flagmemory.tiering.offload.ppu` | 同上（另一条移植路线：vendor 引擎内置实现 + 四个补丁） | 冒烟闭环 + A/B 对照；真模型待排 |
| 寒武纪 MLU590 | **没有** | — | 见 4.4 |

依据 ADR-0014 第 3.5 节第 4 条（解栈耦合）：框架绑定下沉为可选适配层，**池本体不得 import 推理框架**。本文件把这条在分层存储内部再分一次——**分层存储管理器本体也不 import 推理框架**，框架只出现在适配层（`T-5`）。

### 4.2 它们提供什么 / 缺什么

| | 内容 |
|---|---|
| **已提供** | ① 主机侧块池（级二的容量与块表）；② 逐块异步拷贝 + 事件完成上报的搬运通路；③ KV 张量形态归一（把引擎交付的不同 KV 组织形式折成统一条目）；④ 锁页能力探测与两级降级（锁页 → 普通页）；⑤ 批量搬运原语缺失时退逐块拷贝；⑥ 流优先级不可用时退默认流；⑦ 召回匹配与条目命中的诊断标记（命中条目与命中长度逐批可见） |
| **缺** | ① **级三**（更慢介质）整层；② **统一放置决策**——现状的淘汰与召回由推理引擎自己的策略驱动，**没有用途标签作为输入**，因此第二节的 R1–R5「永不下放」在现状里是靠「引擎只把 KV 交给 connector」这个事实成立的，不是靠判据成立的；③ **双指标触发**——现状由引擎侧事件单边驱动，设备侧水位未进判据（`T-1` 在现状里未落地）；④ **抖动抑制**整套（滞回带 / 冷却窗 / 最小驻留 / 搬运预算闸，一条都没有）；⑤ **与池的衔接**——现状直接操作引擎的 KV 张量，不经池的 `alloc_on_stream` / `free_block` / 跨流声明 / 回收屏障，因此 3.4 的六步与五步在现状里**一步都没有**；⑥ **带宽优化**（staging 聚合、批量 DMA）——现状明确不做；⑦ **跨后端统一接口**——三套各导出一个类，形态同构但没有共同的注册与能力查询口（正是第六节第 1 小节 `register_tier_backend` 要补的）；⑧ 寒武纪 MLU590 一家整套缺失 |

一句话总结衔接关系：**搬运通路已经通了三家，放置决策、触发判读、抖动抑制、与池的衔接这四件事一件没有——本文件定义的就是这四件。**

### 4.3 哪些已实测结论直接成为本设计的依据（逐条）

按 ADR-0013 第 3 节第 2 条，已完成的成果不作废、不重做，直接作为依据引用。**凡具体数字一律标「实例」，并标明是哪一栈的口径**（`T-10`）。

| # | 已实测结论 | 在本设计里变成什么 |
|---|---|---|
| 1 | **主机侧池必须大于设备侧池**才构成真两级缓存（实例：64 GiB 档实测门槛约 39.2 GiB；该档召回率 40/40、等效扩容约 +63.2%） | **不变量 `T-8`**（级二容量下界）+ `create_tier_manager` 的启动校验：级二容量 ≤ 级一池容量 ⇒ **报错不启**，不降级成一级 |
| 2 | **单 token 的 KV 成本约 0.14 MiB**（实例：某 8B 量级推荐模型单卡口径）；最大并发 ≈ 池内 token 数 ÷ 单请求上下文 | 换出目标量与级二容量的换算基准（3.2 的默认阈值推导第③项）；`query_tier_watermark` 的条目数换算口径 |
| 3 | **预分配会让设备侧显存读数恒平**（实例：某次实测波动仅 142 MiB） | **不变量 `T-1`**（双指标触发）；E1 条件②必须用引擎侧读数 |
| 4 | **底座块粒度各家不同**（实例：平头哥 PPU 那栈默认块大小为 512 KB/块，推算级二池大小按此计） | **不变量 `T-9`**（搬运粒度不写死常数）；3.2 默认阈值推导第②项 |
| 5 | **召回要靠引擎侧命中信号**（实例：平头哥那栈上，级一池内前缀块被**覆写**而非释放后重放原请求才产生换入；仅被释放的块其标识仍保留，重放只走级一命中） | 换入触发 **I1 必须取引擎侧命中 / 未命中信号**，不能靠「块被释放」这类级一侧事件推断 |
| 6 | **没 record 过的事件查询会误报「已完成」**（寒武纪 MLU590 与平头哥 PPU 原生如此） | 搬运完成确认一律经事件适配器（池的 `I-2`）；3.4 换出第 4 步、换入第 4 步 |
| 7 | **有界同步只有一家是真有界**（昇腾 910C；其余三家的「有界」= 超时上报，含一家轮询实现） | 搬运与回收屏障只许超时 + 轮询，超时不等于失败（池的 `I-11`）；3.4 换出第 6 步 |
| 8 | **锁页能力与批量搬运原语在各栈上不齐**（实例：某栈的驱动不实现批量异步拷贝原语，退逐块拷贝；锁页注册失败需退普通页） | 适配层的两条能力分支 + **降级态必须可查**（3.5 两行）；`query_tier_capability` 的返回内容 |
| 9 | **开启卸载不改变第二层预分配的池数字**（实例：某栈上池容量与池内 token 数与基线一致） | 分层存储**不改**第二层预分配量；容量扩张来自级二，不来自压级一（与 R11 的「压余量」是两件事：R11 压的是向量化负载下的纯余量，由调用方经池的预算视图决定，不是分层存储自己改预分配） |
| 10 | **流与弱引用的退出期崩溃是生态共性缺陷**（平头哥 PPU 与昇腾 910C 两家中招；触发三要素 = 流 + 弱引用 + 被回收） | 搬运流一律经池 `register_stream` 强持有（3.4 换出第 1 步）；分层存储不自持流做弱引用清理（池的 `I-3`） |
| 11 | 上述数字的采集口径已有定稿的画像规范 | **验证基线**：同模型同口径的召回率、等效扩容、搬运代价，作为分层存储上线前后的对照参照 |

### 4.4 哪些只是某一栈的局部事实，不可平移（`T-10`）

| 局部事实 | 属于哪一栈 | 为什么不可平移 |
|---|---|---|
| 池容量与池内 token 数的具体数字（实例：某栈某模型单卡口径） | 单栈 + 单模型 + 单卡 | 随模型、卡数、显存利用率参数变；引用必须同时标栈、标模型、标卡口径 |
| 一次搬运粒度（实例：平头哥 PPU 那栈默认 512 KB/块） | 平头哥那栈 | 其余栈的块组织不同；写死即违反 `T-9` |
| 搬运代价的量级（实例：平头哥那栈冒烟 A/B 中，级一池内命中零代价、超池约 200% 负载时约 +2.1%） | 平头哥那栈 + 冒烟口径 | 冒烟不是真模型；三栈的拷贝通路实现不同（一栈是 vendor 引擎内置实现 + 补丁，两栈是同构自研） |
| 召回触发的具体配方（覆写而非释放） | 平头哥那栈 | 是该栈前缀缓存的实现细节。可平移的是**结论**（换入信号取自引擎侧命中），不是**配方** |
| 锁页是否可用、批量搬运原语是否存在 | 逐栈不同 | 必须运行期探测并上报，不得按某栈的结果预设 |
| 高并发下的算子级异常（某栈上高并发时出现设备侧断言，与搬运无关） | 单栈 + 属 vendor 线问题 | 与分层存储无因果关系，不作为本设计的约束或阈值依据 |

### 4.5 寒武纪 MLU590 的现状与限制，以及该家上的降级形态

**现状**：寒武纪 MLU590 **没有搬运适配层**，且在能力面上是四家里唯一**未声明统一内存句柄、分配器视角已分配量、跨流内存保护、上下文只读观测**（即全部 `L1` 能力）的一家。

**限制（不是待优化承诺）**：

| # | 限制 | 后果 |
|---|---|---|
| 1 | 无搬运适配层 | 该家上分层存储**显式不可用**：`query_tier_capability` 报不可用及原因，换入换出调用一律报错（`T-11`）。**池本体照常工作**，只是退成一级 |
| 2 | 无统一内存句柄 | 池在该家上走张量级形态（四家通用的默认路径），级二搬运无句柄级记账校验基准 |
| 3 | 无跨流内存保护 | 3.4 第 2 步的跨流声明在该家上走**池的降级路径**：池对借用集里每条流各取一次事件凭据，全部确认才放行。回收延迟变长、待回收队列变深，池**显式上报降级态** |
| 4 | 无上下文只读观测 | 归属校验退化为「只校验池自己的登记表」，并上报降级态；不可静默当作校验通过 |
| 5 | 未 record 的事件查询误报「已完成」 | 搬运完成确认必须经事件适配器（池的 `I-2`），该家与平头哥 PPU 同列 |

**该家上分层存储的降级形态**，三档，现行采用第一档、第二档为可做而未做：

| 形态 | 做法 | 依赖的能力级 | 代价 | 状态 |
|---|---|---|---|---|
| **形态一 · 显式关闭（现行）** | 分层存储在该后端不可用并说明原因；池退一级正常工作 | 无 | 该家上没有级二扩容收益 | **现行**。`T-11` 要求的就是这条：显式不可用，不伪装 |
| **形态二 · 张量级搬运（可做，不依赖 `L1`）** | 搬运不走内存句柄，改用框架侧张量的逐块拷贝 + 统一层事件适配器确认；跨流保护走池的降级路径（逐流取凭据）；级二块池用主机侧张量，锁页能力运行期探测 | 只用 `L0`（流、事件、设备侧三键查询）+ 池的降级路径 | 无句柄级记账校验；回收延迟不确定、待回收队列可能变深；搬运带宽未测 | **可做未做**。做它需要该家一次真机实测，排期不在本文件 |
| **形态三 · 句柄 / 跨进程零拷贝路径** | 依赖统一内存句柄与跨进程共享句柄 | `L1` + SDK 证据候选，后端/运行验证未完成 | — | **一律不启用**。该家未声明句柄能力（池的 `I-8`：核心路径只许用 `L0`，`L2`/`L3` 不用），且SDK 证据不等于统一后端接入与运行验证（第七节） |

## 五、不变量清单（本文件是唯一登记处）

**命名空间 = 分层存储子系统内部**，编号 `T-1`…`T-11`。

⚠️ 再钉一次本文件第〇节的约定：`T-n` **不是**池本体的 `I-n`（登记处 = 本仓 `docs/design/显存池概念与设计基础.md` 第三节第 5 小节，命名空间 = 显存池组件内部），**不是**指挥台仓 `tasks/BOARD.md` 的总组任务号 `T-053` / `T-054`（命名空间 = 总组），也**不是**方向门禁号或发布物限制条目号。三套编号互不换算。

违反任一条即为实现缺陷，单测与门禁各钉一次。

| 编号 | 不变量 | 为什么 |
|---|---|---|
| **`T-1`** | **触发判据必须双指标**：凡「水位」类判据，设备侧与引擎侧两侧读数都要取，且都要满足；**单指标读数不得作为任何换入换出决策的唯一输入**。设备侧不可用 ⇒ 报错不启分层存储，不用引擎侧单边数充抵 | 第二层的预分配会让设备侧显存读数恒平（实例：某次实测波动仅 142 MiB），条目的真实涨落只在引擎侧可见。单指标的结果是「要么一次不触发，要么一直触发」。与池的 `I-6` 同源，本层再钉一次 |
| **`T-2`** | **抖动抑制四件默认开且可查**：滞回带（换出高水位 `H` 与预取低水位 `L` 分离，带宽 `H − L` ≥ 一次搬运粒度 × `N`）、冷却窗口、最小驻留、搬运预算闸 + 空转退避。**单阈值一律视为缺陷**；冷却窗**不得**挡住真实请求召回 | 单阈值在阈值附近必然来回跳闸；没有最小驻留，一次换入的成本会被下一刻的换出抹掉；冷却窗挡住真实召回等于「数据在级二却报未命中」，属静默退化 |
| **`T-3`** | **永不下放清单**：**权重、通信缓冲、用途标签为「未声明」的块永不下放**；**临时工作区与激活不进分层** | 前三类是安全约束——通信缓冲由通信方向申请，动它会与通信方向打架；标签缺失时保守是唯一安全解（池的 `I-12` 在本层的等价表述）。后两类是成本判断：其生命周期短于一次搬运往返，下放是净亏 |
| **`T-4`** | **失败不静默退化**：报错，或显式降级并上报降级态，二者之一。**禁止**把换入失败当成未命中、把部分换出报成成功、把空操作报成成功、静默改小搬运量、静默降级锁页或搬运原语 | 静默退化会让上层拿到不满足语义的结果，且事后无法归因。换入失败当未命中这一条尤其危险：它把一个容量错误伪装成一次缓存未命中，现象是「偶尔变慢」，无人会去查 |
| **`T-5`** | **适配层不得被反向依赖**：池本体不 import 推理框架，**分层存储管理器本体也不 import 推理框架**；框架绑定只许出现在搬运适配层。后续回调设计不得反向 import 分层存储；当前没有建池换出回调 | 依据 ADR-0014 第 3.5 节第 4 条（解栈耦合）。反向依赖一旦成立，池与分层存储就被钉死在某一个推理框架的版本面上，且无卡成员跑不了单测 |
| **`T-6`** | **搬运必须经池的流序口**：搬运流一律经池 `register_stream` 登记并由池强持有（不得自持弱引用）；跨流搬运一律先 `declare_cross_stream_use`；完成确认一律经统一后端接口的事件适配器，**不许裸调厂商事件查询** | 流 + 弱引用 + 被回收 = 进程退出期段错误（平头哥 PPU 与昇腾 910C 两家中招）；未 record 的事件查询在寒武纪 MLU590 与平头哥 PPU 上原生返回「已完成」，裸调会把还在拷贝的显存判成搬完（池的 `I-2`/`I-3` 在搬运路径上的落地） |
| **`T-7`** | **搬运与回收屏障的顺序不可换**：换出必须「条目先落级二账本 → 后调 `free_block`」；换入必须「搬运完成确认 → 后交块给调用方」。屏障**只许超时 + 轮询，不许阻塞等待**，**超时不等于失败**，按可恢复态上报 | 账本后行会开出一个窗口：块已进待回收而条目两级都查不到，这期间的请求被判彻底未命中（丢数据）。未确认完成就交块 = 交出内容不全的显存。四家里只有昇腾 910C 是真有界同步，阻塞等待在其余三家上不成立（池的 `I-11`） |
| **`T-8`** | **级二容量必须大于级一池容量**，否则**报错不启分层存储**，不降级成一级 | 已实测：主机侧池必须大于设备侧池才构成真两级缓存（实例：64 GiB 档实测门槛约 39.2 GiB）。级二不大于级一时，分层存储不产生扩容，只产生搬运开销——此时「启动但无收益」比「拒绝启动」更坏，因为它看起来是在工作 |
| **`T-9`** | **搬运粒度与阈值默认值不写死常数**：一次搬运粒度由搬运适配层按后端块大小声明，阈值默认值由能力层按分配粒度、搬运粒度、池容量与单 token 的 KV 成本推导；生效值必须可查 | 底座块粒度各家不同（实例：平头哥 PPU 那栈默认块大小为 512 KB/块）。与池的「档位粒度不写死常数」同源 |
| **`T-10`** | **局部事实不平移**：引用任何实测数字必须标明栈（必要时并标模型与卡口径）；单栈结果不得作为跨栈默认值或阈值依据 | 三栈的搬运通路实现路线不同（一栈是 vendor 引擎内置实现 + 补丁，两栈是同构自研），锁页与批量搬运原语的可用性逐栈不同。把一栈的数字当默认值，等于在另两栈上写死一个错误常数 |
| **`T-11`** | **无搬运适配层的后端上，分层存储显式不可用**：能力查询报不可用及原因，换入换出调用一律报错；**不得伪装可用后每次返回未命中** | 寒武纪 MLU590 现状（4.5）。伪装可用的后果是上层以为有两级缓存、按两级容量做准入，而实际一级——容量判断全错且无从发现 |

### 6.1 分层存储新增的操作

| # | 操作 | 一句话语义 |
|---|---|---|
| 1 | `create_tier_manager` | 在一个既有池上创建分层存储管理器，定下级二容量与各阈值；级二容量不大于级一池容量即报错不启 |
| 2 | `destroy_tier_manager` | 销毁：排空在途搬运、给出级二残留条目与未回级一的块清单 |
| 3 | `register_tier_backend` | 注册一个搬运适配层（某后端一套）；未注册即该后端分层存储不可用 |
| 4 | `classify_placement` | 放置判定：给一块内容返回目标级别 + 命中的规则号 + 本次用到的五条判据读数。**只判定，不搬运** |
| 5 | `evict` | 换出：按目标量或压力等级挑候选、搬运、落级二账本、归还块；如实返回实际换出量 |
| 6 | `promote` | 换入：按条目标识向池要块、搬运、确认完成后交出；失败即报错 |
| 7 | `query_tier_watermark` | 三级占用：级一取自池的双指标（两侧都给），级二取自主机侧账本，级三给「未实现」 |
| 8 | `query_tier_capability` | 本后端分层存储是否可用、已注册的适配层、生效的降级形态与代价、各阈值的生效值 |
| 9 | `query_tier_audit` | 搬运审计：换出 / 换入字节数与次数、抖动抑制四件各自的触发次数、冷却窗内被拒的预取次数、越窗换出次数、屏障超时与隔离计数、级三缺失丢弃计数 |
| 10 | `set_tier_policy` | 改阈值与窗口等可配置项（运行期可改，改完生效值立即可查） |

| 操作 | 参数语义 | 返回 | 错误 |
|---|---|---|---|
| `create_tier_manager` | 池句柄；级二容量；（可选）各阈值与窗口，不给则由能力层推导（3.2） | 管理器句柄 + 生效的阈值与降级形态 | **级二容量 ≤ 级一池容量 → 报错不启**（`T-8`）；该后端无已注册适配层 → 报错（`T-11`）；池的设备侧三键查询不可用 → 报错（`T-1`） |
| `destroy_tier_manager` | 管理器句柄；是否等待在途搬运排空（带超时） | 级二残留条目清单；未回级一的块清单 | 存在在途搬运 → 不静默丢弃，返回清单并报错；排空超时 → 可恢复态上报，不阻塞（`T-7`） |
| `register_tier_backend` | 管理器句柄；后端标识（经统一后端接口解析，**不是芯片型号字符串**）；适配层的能力声明（一次搬运粒度、是否锁页、是否有批量搬运原语） | 注册结论 + 探测到的实际能力与降级项 | 后端标识与池的后端不一致 → 报错；适配层声明的能力运行期探测不到 → 按降级登记并上报，**不静默**（`T-4`） |
| `classify_placement` | 管理器句柄；块标识或级二条目标识 | 目标级别（级一 / 级二 / 级三）+ 命中规则号（R1…R14）+ 五条判据读数（含双指标两侧） | 判据 4 / 5 取不到 → 退用判据 1 + 2 + 5 并标降级，不把频度当 0（2.1）；用途标签取不到 → 按「未声明」⇒ 永不下放（`T-3`） |
| `evict` | 管理器句柄；目标释放量或压力等级；搬运流标识；（可选）是否允许越过最小驻留窗 | 实际换出字节数与条目数 + 候选排序依据 + 是否越窗 | 级二容量不足 → 返回实际量并标「未达目标」，不谎报（`T-4`）；搬运报错 → 条目不落账本、不调 `free_block`，块留 `在用` 并报错（3.5）；跨流未声明 → 报错（`T-6`） |
| `promote` | 管理器句柄；级二条目标识；目标流标识；（可选）是否保留级二副本 | 块标识 + 底座引用 + 实际搬入字节数 | 池容量不足 → **报错**并附池返回的双指标水位，**不许当作未命中**（`T-4`）；条目不在级二 → 报错；冷却窗内的预取 → 返回「被冷却窗拒绝」（真实请求召回不受此限，`T-2`） |
| `query_tier_watermark` | 管理器句柄 | 级一（设备侧 + 引擎侧，**两侧都给**）+ 级二（容量 / 已用 / 条目数）+ 级三（「未实现」） | 级一任一侧取不到 → 报错，不用单边数充抵（`T-1`） |
| `query_tier_capability` | 管理器句柄 | 是否可用及原因；已注册适配层；生效的降级形态与各自代价；各阈值与窗口的生效值 | — （该口恒可用，是降级可观测性的基础） |
| `query_tier_audit` | 管理器句柄 | 见 6.1 第 9 条 | — |
| `set_tier_policy` | 管理器句柄；要改的阈值 / 窗口项 | 改后的生效值 | 违反滞回带约束（`L > H − 一次搬运粒度 × N`）→ 报错，不静默夹取（`T-2`、`T-4`）；把抖动抑制整项关掉 → 报错（四件默认开，`T-2`） |

### 6.2 分层存储向池要什么（依赖池的哪些操作）

下表是 1.4 小节「唯一下行依赖」的逐条展开。**这些操作一条都不新增、不改语义**；分层存储是它们的调用方。

| 池的操作 | 分层存储用它做什么 | 用在哪 |
|---|---|---|
| `alloc_on_stream` | 换入时要一块级一的块（用途标签 = KV 缓存，绑目标流） | 3.4 换入第 1 步 |
| `free_block` | 换出搬完、条目已落级二账本之后归还块 | 3.4 换出第 5 步（顺序由 `T-7` 钉） |
| `register_stream` | 把搬运流登记进池并由池强持有 | 3.4 换出第 1 步（`T-6`） |
| `declare_cross_stream_use` | 搬运流与分配流不同时声明跨流使用 | 3.4 换出第 2 步、换入第 2 步（`T-6`） |
| `drain_stream` | 推进待回收队列，把屏障已确认的块转可复用 | 3.4 换出第 6 步 |
| `query_watermark` | 取级一双指标水位，作触发判据 2 | 2.1 判据 2；3.1 E1 / I2；`query_tier_watermark` 的级一部分 |
| `query_budget` | 取按用途标签聚合的已分配量与负载类型判读 | 2.1 判据 3；R11 / R12 的负载类型分叉 |
| `query_capability` | 读池的实现形态与生效的降级路径，作为自身降级形态判读的输入 | 4.5 形态判读；`query_tier_capability` 的一部分 |
| `verify_block_ownership` | 搬运前后核块归属，账本对不上时据此处置 | 3.5「级二账本与级一块账对不上」那行 |
| `reclaim`（**反向**） | 后续设计经建池回调触发 `evict`；当前无回调，允许分层换出时报 `NotWired` | 3.1 E2；关系见 1.2 第 2 条（池不 import 分层存储，`T-5`） |

除后续换出回调尚需接线外，分层存储复用池已有操作；当前不能把反向回调视为现成能力。用途标签这一项是**池侧已有的口径**（《显存池概念与设计基础》第 4.3 小节，11-25 与设备执行上下文方向联合冻结）——分层存储只**读**标签，不要求谁为标签实现新行为。

## 七、分层存储与通信缓冲协同（SDK 证据与运行能力边界）

本节分两段。**第一段是现行设计，不依赖任何未取证的能力；第二段是前提成立时的优化路径，前提不成立则整段不生效。**

### 7.1 现行设计（不依赖跨进程共享句柄）

| # | 内容 |
|---|---|
| 1 | **通信缓冲永不下放**（`T-3`、池的 `I-12`）。通信缓冲标签的块由通信方向申请，分层存储只在 `classify_placement` 里认这个标签并返回「级一，永不下放」，**不碰它**，也不参与它的回收 |
| 2 | **协同的现行形态 = 只读记账**。分层存储把通信缓冲标签的已分配量从池的 `query_budget` 读出来，作为级一可下放空间的**扣减项**计入放置判据 3；仅此而已，不与通信方向做任何缓冲复用或共享 |
| 3 | **搬运不与通信共用缓冲**。级二搬运用自己的主机侧块池（由搬运适配层持有），不借用通信方向的收发缓冲，也不向其申请锁页内存 |
| 4 | 这条设计**跨四家成立**，只用 `L0` 能力（流、事件、设备侧三键查询）+ 池已有的标签记账，不需要内存句柄、不需要跨进程共享、不需要跨流内存保护 |

### 7.2 优化路径（前提：后端接入并完成生命周期运行验证）

> **前提声明**：四家跨进程共享句柄的 SDK 声明/符号证据已登记在指挥台仓 `inbox/调研-四芯片SDK显存原语面补探-20261103.md`（一句话：只读原语补探，区分双证、仅符号和缺失）。这不证明统一后端、池与通信方向已打通共享或生命周期语义。下表是后续优化设计，须另完成能力声明与运行验证；不属于当前实现承诺。

| 若该能力可用 | 可做的优化 | 收益 | 前提不成立时 |
|---|---|---|---|
| 跨进程共享句柄可用，且通信方向与池在同一设备上下文可互相认句柄 | 级二搬运的主机侧落点可与通信方向的收发缓冲共享同一段锁页内存，省掉一次主机内拷贝 | 省一次主机侧拷贝；锁页内存总占用下降 | 7.1 第 3 条：各用自己的主机侧池，多一次主机内拷贝 |
| 同上 | 换出条目可被另一进程（如独立的级三搬运进程）直接读取，不经本进程 | 级三搬运可与推理进程解耦 | 级三整层未实现（第八节第 2 条），本就不受影响 |
| 同上 | 通信缓冲的生命周期可由句柄登记表跨进程核对，归属校验强度上升 | 归属校验不再依赖单进程账本 | 归属校验走池的 `verify_block_ownership`，寒武纪 MLU590 上退为「只校验池自己的登记表」并上报降级态 |

**三条纪律**，无论该能力将来是否可用都成立：① 优化路径接上**不改本文件第二、三、六节的对外语义**；② 该能力只能出现在搬运适配层与池的能力层，**不得**出现在分层存储管理器本体（`T-5`）；③ 该能力若只在部分芯片上可用，一律按 `L1` 以下处理——**核心路径不得用它**（池的 `I-8`：核心路径只许用 `L0`）。
