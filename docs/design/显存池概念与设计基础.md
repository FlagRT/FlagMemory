## 当前实现边界

当前查询中的 `pool_in_use`、`pool_reusable`、`pool_pending`、`pool_quarantined` 来自本组件显式接管块的账本；文中沿用的「引擎侧」在当前实现里仅指这组池内统计，不是已接入 vLLM 的全局 KV 指标，也不表示自动接管框架全部分配。设备侧三键来自后端设备查询，范围与本池账本不同；历史 vLLM 画像是设计输入，不能充抵当前组件的运行覆盖。`engine_fragmentation` 当前为本池可复用字节除以本池持有字节，非全局引擎碎片率。

池本体已有自管分级块池实现及主机回归；实际入口与限制见 [实现说明](../impl/11-28-分级块池与流有序分配.md)，签名见 [类型存根](../../flagmemory/interfaces/pool.pyi)。当前原生流有序优化关闭，首次芯片验证只覆盖显式张量级自管路径；主机检查不等于真卡通过。业务消费方与通用分层管理器尚未接入；建池可登记换出回调，未登记时 `reclaim(allow_tier_offload=True)` 抛 `NotWired`。接口语言面已定稿为现行口径（ADR-0015，2026-11-05）：类型存根 + 接口文档，C 头触发式。

SDK 原语证据登记在指挥台仓 `inbox/调研-四芯片SDK显存原语面补探-20261103.md`（四家头文件与库符号的只读调查）。寒武纪 MLU590 与平头哥 PPU 有流有序族头文件/符号双证，但平头哥设备属性实际值未确认；昇腾 910C 随现场运行时存在能力分叉；昆仑芯 P800 的兼容异步接口有同步实现限制。虚址/物理页映射在三家有双证、昆仑芯仅兼容层符号；跨进程句柄四家有 SDK 证据。三家有粒度查询声明，昆仑芯原生无粒度声明、兼容符号不足以给出基数（该基数后经运行实测取证补齐 —— 属第三层运行验证事实，非 SDK 层声明，登记见第八节第 4 条；原生无声明不变）。**SDK 证据、后端能力声明和运行验证是三层不同事实**，不据此启用原生池、句柄或跨进程路径。

运行层取证补记（2026-11-09）：流有序分配、虚址映射、跨进程共享、分配粒度与分配器开关五组原语面已在昇腾 910C 与昆仑芯 P800 真机取证收口，事实与证据集中登记于《分层存储概念与设计基础》第十节（登记处 = 指挥台仓 `inbox/取证-四类显存原语两栈与昆仑芯粒度尾巴-20261109.md`，本文不搬正文）。现状口径：流有序优化路径适用面为——昆仑芯 = 「池自己记流序」形态走 cudaMallocAsync ctypes 直调路径可立项（其分配语义为即时生效、非流序延迟）；昇腾 = 确无流有序，独立另一条 VMM 路径（大 VA 预留 + 按需 2 MiB 物理映射）可立项；平头哥 = 未探查；寒武纪 = 已取证（2026-11-13，登记见《分层存储概念与设计基础》第十节补记三：流序「池自己记流序」形态事实面全好且 torch 层无门禁三通路、VMM 路径机制齐备但物理粒度 32 MiB）；跨进程 import 两家均无可用运行证据。自管流序与事件屏障维持当前基线不变。

## 一、池的分层结构

### 1.1 三层各是谁

显存这件事上已经各有一个池，我方交付的是最上面那一层。

| 层 | 持有者 | 它管什么 | 四家现状 |
|---|---|---|---|
| **第一层 · 厂商缓存分配器** | 芯片厂商随框架扩展提供 | 把设备驱动的裸分配包成缓存复用，减少频繁申请释放 | 昆仑芯 P800 / 平头哥 PPU / 寒武纪 MLU590 在框架自带的分配器命名空间里；昇腾 910C 由其框架插件提供一份 |
| **第二层 · 推理框架预分配池** | 推理引擎 | 服务启动时按「显存利用率」参数一次吃满空闲显存，之后在自己池内切块 | 四家都有，且已实测（第六节） |
| **第三层 · 显存池管理器（我方交付）** | `flagmemory.pool` | 块的分级与复用、流有序分配与归还、水位与碎片口径、压力回收、预算仲裁、块归属校验 | 本文件定义 |

### 1.2 我方池与厂商缓存分配器是什么关系

**答：在其上做分级块池。不替代，不旁路。**

| 可选关系 | 取舍 | 理由 |
|---|---|---|
| 替代厂商缓存分配器 | ✗ 不采用 | 替代要求池能拿到稳定的裸设备内存并接管全部分配路径。四家只有昇腾的内存句柄底下接的是厂商裸分配原语；昆仑芯与平头哥的句柄底下接的就是厂商缓存分配器本身，寒武纪未声明句柄能力。替代在四家里最多一家成立。 |
| 旁路厂商缓存分配器（自取裸原语建池） | ✗ 不采用 | 旁路要绕过设备方向统一后端接口直接调厂商原语，与「池只依赖统一后端接口」的解栈要求相反；SDK 头文件与导出符号调查只提供原语候选，不证明统一后端或池已接入；旁路也不属于当前实现。 |
| **在其上做分级块池** | ✓ **采用** | 池把底座当作「一次拿到的大块来源」，自己只管块的分级、归属、流序与账本。这条在四家上一致成立，且不要求池知道底座是裸内存还是缓存分配器。 |

由此推出一条贯穿全文的设计前提：**池不得假设自己拿到的是裸内存。** 同一个内存句柄在不同后端下的底座不同，这件事要求写进 11-25 联合冻结的接口文件（第四节）。

### 1.3 实现形态：默认张量级，句柄形态是优化路径

| 形态 | 适用 | 做法 |
|---|---|---|
| **张量级分级块池（默认，四家通用）** | 四家全部 | 以框架侧的空张量申请作底座拿到块，池只管块的分级、归属与归还账本，不碰裸指针 |
| 内存句柄形态（优化路径） | 昇腾 910C / 昆仑芯 P800 / 平头哥 PPU | 在声明了统一内存句柄能力（`L1`）的三家上启用，走能力分支 |

寒武纪 MLU590 未声明内存句柄能力，因此句柄形态在该家上不启用，池走默认张量级路径。两种形态对上层**暴露同一套接口**，形态差异只在能力层内部（`flagmemory.caps`）分支。

### 1.4 职责边界

| | 内容 |
|---|---|
| **池负责** | 块分级与复用；按流分配与归还；流序屏障；水位与碎片的双指标取数；压力回收（进程内）；按用途标签的预算仲裁；块归属校验；池自身账本的一致性审计 |
| **池不负责** | 设备上下文的创建 / 切换 / 销毁（一律不做，见不变量 `I-4`）；设备级故障自救（只上报，`I-5`）；厂商原语的直接调用（只经统一后端接口）；上层的放置策略与调度决策（池只提供水位、碎片与预算视图）；通信缓冲的回收（只记账，不回收） |
| **池上面谁调用** | 推理与训练运行支撑（块的主要消费方）；分层存储与 KV 卸载适配层（向池要块、按池的水位决定换入换出）；调度方向（读预算与水位视图做准入）；监控诊断方向（读双指标） |
| **池下面依赖什么** | **只依赖设备方向的统一后端接口**（设备级显存三键查询、流、事件、有界同步、图捕获、内存句柄与其登记表、上下文只读观测）。**不依赖厂商原语，不 import 推理框架。** |

## 二、块与流的关系

### 2.1 块是什么

**块（block）** = 池向底座取得的一段设备显存及其账目；对外每次出借另发当前租约。底座身份与租约身份分离。块的账目字段：

| 字段 | 语义 |
|---|---|
| 租约号 `block_id` | 进程内跨池唯一、每次租用更新的不透明凭据；归还或隔离立即撤销。旧号统一报无效或失效，不保存全部退休编号；不是防猜测权限令牌 |
| 底座号 `storage_id` | 稳定底座身份；底座复用时不变，不能用租约号相等证明底座复用 |
| 档位与字节数 | 所属分级档位，以及实际字节数 |
| 底座引用 | 张量级形态下是底座张量；句柄形态下是统一层内存句柄号。**池不持有厂商指针** |
| 所属流 | 分配时所在流的标识；缺省表示默认流 |
| 用途标签 | 权重 / KV 缓存 / 激活 / 通信缓冲 / 临时工作区 / 未声明 |
| 跨流借用集 | 曾被哪些流读写过（跨流保护用，见 2.4） |
| 屏障凭据 | 待回收期间用于判「流上操作是否跑完」的事件凭据 |
| 状态 | 见 2.2 |

### 2.2 块的生命周期状态机

六个状态，外加一个旁路状态。

| 状态 | 含义 | 块在哪 |
|---|---|---|
| `申请中` | 池已受理一次分配请求，正在定档、找可复用块或向底座取新块 | 不可被任何调用方看见 |
| `在用` | 已交给调用方，归属某条流 | 调用方手里 |
| `待回收` | 调用方已归还，但所属流（及跨流借用集里的流）上的操作未确认完成 | 池的待回收队列 |
| `可复用` | 流序屏障已确认完成，块回到对应档位的空闲表 | 池的分级空闲表 |
| `已归还` | 块被交回底座（底座张量释放 / 句柄成对释放），块对象终结 | 不存在 |
| `隔离` | 账本不符、当前租约明确设备/上下文错误、事件或底座释放错误 | 池的隔离区，**不复用、不释放、只上报** |

状态迁移：

| 从 | 到 | 触发 | 失败时 |
|---|---|---|---|
| （无） | `申请中` | 收到按流分配请求 | 参数非法 → 直接报错，不建块 |
| `申请中` | `在用` | 命中可复用块，或向底座取块成功 | 容量不足 → **报错**（不静默降低档位、不静默缩小尺寸） |
| `在用` | `待回收` | 调用方归还 | 跨池、重复或过期租约 → 报错且不改变当前块；当前租约明确归属不符 → 隔离并托管 |
| `待回收` | `可复用` | 流序屏障确认所属流与跨流借用集上的操作全部完成 | 正等待到期 → 保留 `待回收` 并报告可恢复态；零等待只观察，不计超时，不按到期次数隔离 |
| `可复用` | `申请中` | 被下一次分配命中复用 | — |
| `可复用` | `已归还` | 压力回收、池销毁、或碎片整理决定交回底座 | 底座释放报错 → 转 `隔离` 并上报 |
| 任意 | `隔离` | 账本不一致 / 当前租约明确归属错误 / 事件错误 / 底座释放错误 | — |
| `隔离` | （无） | 不自动迁出。无安全证明时由进程托管保留到退出，不提供强制释放 | — |

两条要点：
- **归还（`在用`→`待回收`）与可复用（`待回收`→`可复用`）是两件事。** 调用方看到的「还回去了」只到 `待回收`；池绝不在流序未确认时把块交给下一个人。
- **`隔离` 是终态。** 池宁可泄漏一块、把问题暴露出来，也不把一块状态不明的显存再交给别人。隔离量是对外可查的审计指标。

### 2.3 块归属哪个流

- 块在**分配时**绑定所属流，由分配请求显式给出；不给则绑默认流。
- 所属流决定回收屏障打在哪条流上：块归还后，池在所属流上取事件凭据，等该事件确认完成才放行到 `可复用`。
- **池持有流对象必须强持有**（不变量 `I-3`）：流 + 弱引用 + 被回收这三件事同时成立会导致进程退出期段错误，平头哥 PPU 与昇腾 910C 两家在四家矩阵里中招，且是最难查的一类故障。因此池为每条见过的流在流登记表里保留强引用，直到安全关闭；关闭中或隔离托管继续持有，不做基于弱引用的自动清理。
- **池不改流优先级，也不靠流优先级表达回收次序**：四家里流优先级的可设置性没有一家能全指望（一家丢参数、一家退化成单档）。回收次序由池自己的档位与用途标签决定。

### 2.4 跨流使用怎么保护

跨流使用 = 一块显存在 A 流上分配，却被 B 流读写。若只在 A 流上打屏障，B 流还没跑完就可能把块复用出去，踩内存。

| 路径 | 条件 | 做法 |
|---|---|---|
| **能力分支（首选）** | 芯片声明了跨流内存保护能力（`L1`：昇腾 910C / 昆仑芯 P800 / 平头哥 PPU） | 调用方跨流使用前，经统一后端接口登记跨流保护；池把该流并入块的跨流借用集，屏障要等所属流与借用集里所有流都确认完成 |
| **降级路径** | 芯片未声明该能力（寒武纪 MLU590） | 池自己记跨流借用集，屏障改为「对借用集里每条流各取一次事件凭据，全部确认才放行」。代价是回收延迟变长、待回收队列变深；池**显式上报降级态**，不静默 |

两条路径的**对外语义完全相同**（跨流使用必须先声明，未声明就跨流使用属调用方错误）。差别只在池内部的屏障成本，以及降级态下的回收延迟。

降级路径的边界要写清：**池不承诺在未声明跨流使用的情况下保护跨流读写。** 这一条在能力分支与降级路径下都成立，不随芯片变化。

## 三、分配 / 复用 / 回收 / 碎片四类操作

每类给出前置条件、后置条件、失败行为。四类操作共享一条总纪律：**失败就报错，不静默退化**——池可以降级（走降级路径并上报降级态），不可以悄悄给出一个不满足请求语义的结果。

### 3.1 分配

| | 内容 |
|---|---|
| **语义** | 按请求的字节数定档，从该档空闲表取一块可复用块；取不到则向底座取新块；交给调用方并绑定所属流与用途标签 |
| **前置条件** | ① 池已创建且未销毁；② 调用方处在池所属的设备上下文内（池不建上下文）；③ 请求字节数 > 0；④ 所属流（若给）已在池的流登记表内（默认流已登记，其他流需显式登记并强持有）；⑤ 用途标签取自约定枚举，不给则按「未声明」 |
| **后置条件** | ① 返回当前租约快照；用 `access_block(block_id)` 取得可消费底座；② 块状态 = `在用`；③ 池账本中该块的所属流、用途标签、档位、字节数已登记；④ 按用途标签聚合的已分配量已更新；⑤ 若走了降级路径（如句柄能力缺失），降级态可被查询 |
| **失败行为** | 容量不足 → **报错**（错误里带当前双指标水位与该档空闲量），不自动缩小请求、不自动换档、不自动触发阻塞等待；能力未声明而被要求句柄形态 → 报错（不静默退化为张量级，形态选择由能力层在池初始化时一次定下，不在单次分配里偷换）；参数非法 → 报错；设备级故障 → 上报，不自救 |
| **不做的事** | 不自建设备上下文；不调整流优先级；不为了满足一次请求而强制回收别人的 `在用` 块 |

档位设计的两条约束：
- **档位粒度不写死常数。** 底座的块粒度在四家上不同（实例：平头哥 PPU 那栈的默认块大小是 512 KB），档位表必须由能力层按后端给出的分配粒度推导，池本体不内嵌数字。
- 档位数量与跨档策略属实现可调参数，不属本文件冻结范围；冻结的是「定档失败即报错」这条语义。

### 3.2 复用

| | 内容 |
|---|---|
| **语义** | 一块已确认流序完成的块（`可复用`）被下一次分配命中，不回底座 |
| **前置条件** | ① 块状态 = `可复用`（即屏障已确认，`待回收` 的块**不可**被复用）；② 档位匹配请求；③ 块未处在 `隔离` |
| **后置条件** | ① 块状态 `可复用`→`申请中`→`在用`，每次签发新租约号，底座号不变；② 块的所属流改绑为本次请求的流，跨流借用集清空；③ 用途标签改写为本次请求的标签；④ 复用计数更新（对外可查，是碎片与命中率的取数来源之一） |
| **失败行为** | 命中的块在改绑前发现账本与底座不一致 → 转 `隔离` 并报错，分配请求继续尝试下一块候选；连续命中隔离 → 报错并上报账本一致性告警 |
| **复用优先级** | 生命周期短的用途优先复用。激活是块复用的主战场；临时工作区最优先回收；**权重与通信缓冲从不进入复用池**（只记账）；标签为「未声明」的块按最保守处理：不回收、不复用 |

### 3.3 回收

回收分两档：**归还**（调用方交回一块）与**压力回收**（池在水位压力下主动释放）。

| | 归还 | 压力回收 |
|---|---|---|
| **语义** | 块从 `在用` 进 `待回收`，等屏障确认后转 `可复用` | 把 `可复用` 的块交回底座（`已归还`）；登记换出回调后允许换出时先经回调换出并计入结果，未登记仍抛 `NotWired` |
| **前置条件** | ① 块由本池发出；② 归属校验通过（块的设备与上下文与池一致）；③ 调用方已提交工作并登记相关流，归还后不再使用旧别名 | ① 池已创建；② 存在 `可复用` 块；分层换出要求建池时已登记换出回调；③ 调用方给出回收目标量或压力等级 |
| **后置条件** | ① 块状态 = `待回收`，屏障凭据已取；② 当前租约撤销，Python 别名无法撤销但不得继续使用；③ 屏障确认后状态 = `可复用` | ① 已释放字节数与剩余 `可复用` 量可查；② 双指标水位更新；③ 未达目标量时**如实返回实际释放量**，不谎报成功 |
| **失败行为** | 跨池、重复或过期租约 → `OwnershipViolation`，不改变健康块或新持有者；当前租约明确设备/上下文不符才隔离并托管。**绝不依赖厂商报错来发现这类错误**（不变量 `I-1`）：昇腾的裸释放原语对二次释放与非法指针静默返回成功，昆仑芯的缓存分配器删除如实报错，两家行为相反，所以拦截必须由池自己的账本完成（并沿用统一层的句柄登记表，不重造第二套） | 屏障超时 → 不阻塞，按可恢复态上报并保留在 `待回收`；底座释放报错 → 块转 `隔离` 并上报；**设备级故障一律只上报不自救**（不变量 `I-5`）：四家里只有昇腾有设备级真重建，另三家分别是无原语、确认不具备、以及「原语返回成功但之后设备全废」，任何自救路径在三家上跑不通 |

屏障的实现约束（不变量 `I-2`）：**判「块上的操作跑完了」不许裸调厂商事件查询。** 寒武纪 MLU590 与平头哥 PPU 上，没有 record 过的事件查询原生返回「已完成」——裸调会把一块还在用的显存判成可回收。池一律走统一后端接口已修正的事件适配器。

有界同步的约束：四家里只有昇腾是真有界，其余三家的「有界」= 超时上报（含一家是轮询实现）。因此回收屏障**只许用超时 + 轮询，不许用阻塞等待**，且**超时不等于失败**，要作为可恢复态上报。

### 3.4 碎片

| | 内容 |
|---|---|
| **语义** | 对外给出碎片口径与碎片整理动作：把分散的 `可复用` 块合并或交回底座，提高下一次大块分配的成功率 |
| **前置条件** | ① 参与整理的块状态必须是 `可复用`（`待回收` 与 `在用` 一概不动）；② 整理期间不改变任何 `在用` 块的地址与归属 |
| **后置条件** | ① 返回整理前后的双指标碎片读数；② 被交回底座的块状态 = `已归还`；③ 整理未改善时**如实返回「无改善」**，不把一次空操作报成成功 |
| **失败行为** | 底座释放报错 → 相关块转 `隔离` 并上报；整理过程中发现账本不一致 → 立刻停止整理并上报，不继续动块 |
| **取数口径（不变量 `I-6`）** | **双指标：设备侧 + 引擎侧，缺一不可。** 第二层的预分配会把设备侧显存读数压成恒平（实例：某次实测中设备侧波动仅 142 MiB），块的真实涨落只在引擎侧指标里可见。只看设备侧会误判成「池没有动态」或「存在泄漏」；只看引擎侧则看不到池外部的占用。 |
| **价值场景** | 碎片整理的价值场景是**生成式与混合负载**。向量化（embedding）类负载的池是整块分配、本来无碎片，实测中「可扩展段」这类开关对该负载无可测效果——因此碎片整理在向量化负载上不承诺收益，这是现状而非待优化项。 |

### 3.5 不变量清单（本文件是唯一登记处）

命名空间 = 显存池组件内部。违反任一条即为实现缺陷，单测与门禁各钉一次。

| 编号 | 不变量 | 为什么 |
|---|---|---|
| **`I-1`** | **回收不依赖厂商报错**：池以当前活租约映射拦截跨池、重复与过期凭据且不改变当前块；底座身份独立，句柄形态沿用统一层登记表 | 四家行为相反：昇腾的裸释放对二次释放静默返回成功，昆仑芯的缓存分配器删除如实报错。依赖厂商报错等于在一家上完全失效 |
| **`I-2`** | **判完成不裸调厂商事件查询**：一律走统一后端接口的事件适配器 | 寒武纪与平头哥上，未 record 的事件查询原生返回「已完成」，裸调会把在用显存判成可回收 |
| **`I-3`** | **池持有流必须强持有，禁止弱引用自动清理** | 流 + 弱引用 + 被回收 = 进程退出期段错误，平头哥与昇腾两家中招 |
| **`I-4`** | **池绝不自建、切换或销毁设备上下文**，只在调用方既有上下文内工作 | 昆仑芯平台只允许一个上下文，第二次创建直接失败，抢建会让框架起不来；寒武纪未声明该能力 |
| **`I-5`** | **设备级故障只上报不自救**：压力回收只做进程内回收（释放可回收块、触发换出），不做设备重建 | 四家里只有昇腾有设备级真重建；另三家分别是无原语、确认不具备、以及原语返回成功但设备随后全废 |
| **`I-6`** | **水位与碎片取数是双指标**：设备侧 + 引擎侧必须同时给，单指标读数不得作为任何池内决策的唯一输入 | 预分配使设备侧读数恒平，单指标会误判「无动态」或「泄漏」 |
| **`I-7`** | **预算仲裁必须区分负载类型**：向量化负载的池是**纯余量**（可压），生成式负载的池是**真实并发容量**（压了就掉并发）。只看水位数字不看负载类型的仲裁一律视为缺陷 | 同一个「显存利用率」参数在两类负载下语义不同；生成式上该参数从高压到低，并发能力相差数倍 |
| **`I-8`** | **池的核心路径只许用 `L0`（四家齐备）能力**；`L1` 一律走能力分支并在缺失时降级；`L2` / `L3` 一律不用（仅可作诊断增强） | 核心路径一旦用上非齐备能力，池在缺该能力的芯片上就不是降级而是不可用 |
| **`I-9`** | **池不假设拿到的是裸内存**，也不假设底座是厂商缓存分配器；底座形态差异只在能力层体现 | 同一个内存句柄在四家底下接的东西不同（一家接裸分配原语，两家接缓存分配器，一家未声明） |
| **`I-10`** | **失败不静默退化**：报错或显式降级并上报降级态，二者之一；禁止自动缩小请求、自动换档、把空操作报成成功、把部分成功报成成功 | 静默退化会让上层拿到不满足语义的结果，且事后无法归因 |
| **`I-11`** | **回收屏障不许阻塞等待**，一次排空或关闭的全部块共享单调钟截止时间；零等待只观察，正等待到期可恢复且不计次隔离；后端单次查询须非阻塞 | 四家里只有昇腾是真有界同步，其余三家的「有界」= 超时上报 |
| **`I-12`** | **权重与通信缓冲永不被池回收或复用**，只记账；用途标签为「未声明」的块按最保守处理（不回收、不复用） | 通信缓冲由其他方向申请，池动它会与通信方向打架；标签缺失时保守是唯一安全解 |

池本体另有两条来自落点决策的结构性约束，不在上表但同级：**池本体不得 import 任何推理框架**（框架绑定下沉为可选适配层），**池本体的测试不得依赖真卡**（真卡部分单独标记）。

### 4.2 签名意图

下表的「参数语义 / 返回 / 错误」是接口契约，不是实现签名；具体形参名与类型以 `flagmemory.interfaces` 的类型存根为准。

| 操作 | 参数语义 | 返回 | 错误 |
|---|---|---|---|
| `create_pool` | 后端标识（经统一后端接口解析，不是芯片型号字符串）；设备序号；实现形态（自动 / 强制张量级 / 强制句柄形态）；档位表来源（默认由能力层按分配粒度推导）；负载类型（向量化 / 生成式 / 混合，用于 `I-7` 的预算仲裁） | 池句柄 + 生效的实现形态与降级态 | 不在既有设备上下文内 → 报错（池不建上下文，`I-4`）；强制句柄形态而该后端未声明该能力 → 报错，**不静默退化**（`I-10`） |
| `destroy_pool` | 池句柄；是否等待待回收排空（带超时） | `DestroyReport` 的已交回量、待回收/在用/隔离清单、`closing`、`completed`、`custody_id` | 有在用块抛 `LeakDetected` 并附报告；未完成保持 `destroyed=False`，可归还、排空、重试关闭；资源进程级强托管 |
| `alloc_on_stream` | 池句柄；字节数；流标识（缺省 = 默认流）；用途标签（缺省 = 未声明） | 当前租约快照（`block_id`、`storage_id`、档位与字节数）；公开 `access_block` 取底座 | 容量不足 → 报错并附双指标水位与该档空闲量；字节数非法 → 报错；标签不在枚举内 → 报错 |
| `free_block` | 池句柄；块标识 | 块的新状态（`待回收`） | 跨池/过期/重复租约报错且无块状态副作用；当前租约明确归属错误才隔离并托管（`I-1`） |
| `register_stream` | 池句柄；流对象 | 池内流标识 | 流对象无效 → 报错。**池对该流转为强引用并保持到池销毁**（`I-3`） |
| `declare_cross_stream_use` | 池句柄；块标识；另一条流的标识 | 更新后的跨流借用集 | 块不在 `在用` → 报错；后端声明了跨流保护能力则同时经统一层登记，未声明则只记池内借用集并上报降级态 |
| `drain_stream` | 池句柄；流标识（缺省 = 全部）；超时 | 本次转入 `可复用` 的块数与字节数；仍在 `待回收` 的深度 | 零等待只观察；正等待到期可恢复，不按次数隔离；所有块共享截止时间（`I-11`） |
| `query_watermark` | 池句柄 | 设备侧（总量 / 已用 / 空闲）+ 引擎侧（池内已分配 / 可复用 / 待回收 / 隔离），**两侧都给**（`I-6`） | 设备侧三键查询不可用 → 报错，不用引擎侧单边数充抵 |
| `query_fragmentation` | 池句柄 | 双指标碎片读数 + 各档空闲块分布 + 最大可分配连续量 | 同上 |
| `compact` | 池句柄；目标档位（缺省 = 全档）；是否允许交回底座 | 整理前后双指标读数 + 被交回字节数 | 账本不一致 → 立刻停止并上报，不继续动块；无改善 → 如实返回「无改善」（`I-10`） |
| `reclaim` | 池句柄；目标释放量或压力等级；是否允许触发分层换出 | 实际释放量与分层换出量（登记回调并允许换出时） | 未登记回调而 `allow_tier_offload=True` → `NotWired`；达不到目标量如实报告；**不做任何设备级恢复**（`I-5`） |
| `verify_block_ownership` | 池句柄；块标识 | 校验结论（设备 / 上下文 / 账本三项分别给） | 上下文只读观测能力缺失（寒武纪）→ 退化为「只校验池自己的登记表」并上报降级态；不可静默当作校验通过 |
| `query_budget` | 池句柄；（可选）按用途标签筛选 | 按标签聚合的已分配量 + 当前负载类型下的可压余量判读（向量化 = 余量，生成式 = 并发容量，`I-7`） | 标签聚合不可用（设备方向未提供聚合口）→ 用池自己的统计并标明来源 |
| `query_capability` | 池句柄 | 实现形态；启用的 `L1` 能力分支；生效的降级路径清单；各降级的代价说明 | — （该口恒可用，是降级可观测性的基础） |
| `query_audit` | 池句柄 | 在世块数；待回收深度；隔离量与隔离原因分布；复用命中率 | — |

### 4.2.1 当前租约访问与资源寿命

`access_block(block_id)` 返回当前在用租约的实际可消费底座，`block_view` 只给当前租约快照。归还返回的快照不授予继续访问权。Python 任意张量别名无法撤销：调用方须归还前提交工作、登记相关流并建立跨流数据依赖；归还后不得用旧别名读写或排入工作。借用流登记只保护回收寿命，不建立数据依赖。

底座 `allocate(nbytes, device_index=0, *, stream)` 必须在目标流分配或建立首次使用就绪关系；私有映射票据不满足访问契约。登记流前由后端 `validate_stream_device` 核设备，事件使用池设备号。无上下文只读观测时明确 `context_ok=None` 并附降级说明，不当作通过。

关闭中禁止新分配/登记/声明/访问，已有租约仍可归还。进程托管强持有池、底座、后端、分配器、流及已有事件；`list_custodied_pools()` 查各状态块数/字节数，`recover_custodied_pool(custody_id)` 找回池继续处置。全部安全完成自动注销，隔离无安全证明时保留到进程退出；普通变量和报告寿命不承担安全责任。开放且无隔离的池仍须调用方显式关闭，不能丢变量代替关闭。等待值仅接受有限非负数，拒绝布尔值；公共截止时间约束轮询，不抢占后端查询或释放。

### 4.3 内存句柄与用途标签（11-25 与设备方向联合冻结的部分）

**本小节的内容已与设备执行上下文方向联合冻结（2026-11-05 双方认可）。** 冻结文件 = 公共协作仓 `dev/device-context/docs/HANDLE_AND_POOL_INTERFACE_FREEZE_20261105.md`，冲突时以冻结文件为准；本节保留池侧解读（依据 ADR-0013 第 3 节第 4 条：只冻接口、不合写实现）。

沿用设备方向统一后端接口**既有的五个公共字段**（句柄号、种类、后端名、设备序号、字节数），池侧不要求改其中任何一个的含义。新增两项：

| 新增字段 | 语义 | 谁填 | 谁解释 |
|---|---|---|---|
| **用途标签** | 这块显存是干什么的 | 申请方 | 池 |
| 所属流（可选） | 分配时所在流的标识（**是标识，不是流对象**，避免生命周期纠缠） | 申请方 | 池 |

用途标签枚举（六类，可增不可改语义）：

| 标签 | 含义 | 池的处理 |
|---|---|---|
| 权重 | 模型参数，整个服务生命周期常驻 | 永不回收，只记账（`I-12`） |
| KV 缓存 | 推理上下文缓存 | 可分页、可降级到主机侧（分层存储的主对象） |
| 激活 | 前向 / 反向中间结果 | 短生命周期，优先复用，块复用的主战场 |
| 通信缓冲 | 集合通信的收发缓冲 | **不得被池回收**，只记账（`I-12`） |
| 临时工作区 | 算子工作空间 | 最优先回收 |
| 未声明 | 申请方没给 | 最保守：不回收、不复用（`I-12`） |

标签必须落在句柄上而不是池内部，原因是**通信缓冲那一类由别的方向申请**——池只有从句柄上看到标签，才知道「这块别动」。这是「通信缓冲与显存生命周期协同」那条交付条目的接口前提。

联合冻结那份文件里还要落定三件池侧依赖的事实：
1. **同一句柄在不同后端下的底座不同，池不得假设拿到裸内存**（`I-9`，需要接口文件上有一句话落定，避免两边各自假设）；
2. **持有流必须强持有、不许弱引用**，这条写进接口文件的使用约束，不只在池的代码里（`I-3`）；
3. **寒武纪缺内存句柄能力是「确认不具备」还是「未验证」**要有明确状态——两者对池是两种写法：确认不具备则池永久按降级路径处理该家。

池侧不要求设备方向做池化、碎片整理、峰值或扩容策略，也不要求其为用途标签实现任何行为——**标签只透传**。

## 五、接口的语言面

招标口径要「接口头文件与接口文档」。本节定这个「头文件」用什么语言面。

### 5.1 现行方案

**以 Python 类型存根（`.pyi`）作为接口声明的机器可读形态，加接口文档，共同充当招标要求的「接口头文件」。** 落点 = `flagmemory/interfaces/`（存根）+ `docs/design/` 与联合冻结的那份接口文件（文档）。

理由：

| 理由 | 内容 |
|---|---|
| 消费方都在 Python 侧 | 现有资产是纯 Python；四家栈的池消费方（推理引擎侧的连接件、分层存储适配层、画像探针）全在 Python 侧 |
| 此刻造 C ABI 等于为空气建设 | 没有任何已知的非 Python 消费方。一套无人消费的 C 接口既无法被验证，也会立刻漂移 |
| 工作量 | 现在出 C 头 + 绑定会把最小可运行实现那条出口的工作量翻倍，而翻倍换来的能力当前无人使用 |
| 可检验性 | 类型存根能被类型检查器与单测直接校验，属可持续门禁；手写 C 头与 Python 实现的一致性只能靠人眼 |

**同时显式留一条限制**：C 头为触发式交付，触发条件写死两条，任一满足即启动——① 出现**非 Python 消费方**（别的方向或外部要以 C/C++ 链接方式调用池）；② **验收方明确要求 C 形态**。触发后以本文件第四节的接口契约为准生成 C ABI 头 + 语言绑定，并把它登记为新的接口事实源；契约本身不随语言面改变——这也是第四节把「参数语义 / 返回 / 错误」写成契约而不是形参签名的原因。未触发前不提前建设。

### 5.2 替代方案与其代价

替代方案 = 直接出 C 头文件 + Python 绑定。它的收益是对招标「接口头文件」四个字最字面的对齐，以及为将来的 C / C++ 消费方预留；代价是三项：当前零消费方，接口无从验证，等于先冻结一份没人用过的 ABI；绑定层要与池本体同步演进，每次接口变动是两处改动加一次一致性核对；并且会把最小可运行实现那条出口的工作量翻倍，挤占池核心语义的实现时间。

**状态：已拍板（ADR-0015，2026-11-05 用户答「按选项一」）。现行口径 = 5.1 的类型存根 + 接口文档，C 头触发式；5.2 的替代方案与其代价保留作决策背景，不是待选方案。**

## 六、依据章：已完成的显存画像结论

本节是**设计输入与验证基线**，不是本文档主体。九项结论按 ADR-0013 第 3 节第 2 条不作废、不重做，直接作为池的依据引用。

| # | 结论 | 对池的作用 |
|---|---|---|
| 1 | **显存峰值算式** = 驱动占用 + 权重 + 显存利用率 × 空闲显存 + 激活 + 图捕获开销（各项以 GiB 计）。峰值**几乎与批量 / 序列长度 / 最大上下文长度无关**，唯一大杠杆是显存利用率参数 | 池的预算模型：可调的只有那一个杠杆，池的仲裁要瞄准它，而不是去调批量 |
| 2 | **单 token 的 KV 成本 0.14 MiB**（实例：某 8B 量级推荐模型单卡口径）；最大并发 ≈ 池内 token 数 ÷ 单请求上下文 | 档位表与并发容量换算的输入；分层存储换出粒度的参照 |
| 3 | **显存利用率参数的语义随负载变化**：向量化服务的池是纯余量（可放心压到较低档），生成式服务的池是真实并发容量（实例：该参数由 0.9 压到 0.4，并发能力从约 69.7 倍降到约 15.3 倍） | 直接是不变量 `I-7`：预算仲裁必须区分负载类型 |
| 4 | **主机侧池必须大于设备侧池**才构成真两级缓存（实例：64 GiB 档实测验证，门槛约 39.2 GiB；该档召回率 40/40、等效扩容约 +63.2%） | 分层存储的放置规则前提；池的换出目标容量下界 |
| 5 | **四家的显存利用率实测同向**（昇腾 91%→43% / 平头哥 88~90% / 昆仑芯 93.5%→25% / 寒武纪 89.3%→39.9%，且寒武纪上预热后吞吐无差） | 「池是纯余量」这个结论跨四家成立，是压力回收敢做的底气 |
| 6 | **预分配会让设备侧显存读数恒平**（实例：实测波动仅 142 MiB），块的涨落只在引擎侧指标里可见 | 直接是不变量 `I-6`：双指标取数 |
| 7 | **「可扩展段」类开关对向量化负载无可测效果**（池是整块分配，本来无碎片） | 碎片整理的价值场景界定在生成式与混合负载 |
| 8 | **底座块粒度各家不同**（实例：平头哥那栈默认块大小为 512 KB/块） | 档位粒度不写死常数，由能力层按后端分配粒度推导 |
| 9 | 以上数字的采集口径已有定稿的画像规范 | **验证基线**：同模型同口径的上述数字，作为池上线前后的对照参照 |

## 七、能力分级与降级路径对照

分级定义与完整对照见调研《四芯片显存能力对照与池抽象分级》；本节只给池实现要查的那几行。

| 级 | 范围 | 池的用法 |
|---|---|---|
| `L0` 四家齐备 | 设备级显存三键查询、流、事件、有界同步（语义有差）、图捕获、探针级恢复、多卡、流优先级范围可读 | **核心路径只许用这一级**（`I-8`） |
| `L1` 三家有（缺寒武纪） | 统一内存句柄、分配器视角已分配量、跨流内存保护、上下文只读观测 | 走能力分支，缺则按下表降级 |
| `L2` 两家 | 设备上下文生命周期 | 一律不用（`I-4`） |
| `L3` 一家 | 厂商数值错误码表、设备级真重建 | 一律不用，仅作诊断增强（`I-5`） |

五条降级路径：

| 缺什么 | 池怎么走 | 代价 |
|---|---|---|
| 统一内存句柄 | 退张量级池：以框架侧空张量作底座，池只管分级、归属与账本，不碰裸指针（**这同时是四家通用的默认路径**） | 失去句柄形态的记账校验基准 |
| 上下文生命周期 | 池绝不自建上下文；归属校验走只读观测，连观测都没有的那家退为「只靠池自己的登记表」 | 该家上归属校验强度下降，须靠账本审计补 |
| 真有界同步 | 回收屏障用超时 + 轮询，不用阻塞等待；超时按可恢复态上报 | 回收延迟不确定，待回收队列可能变深 |
| 厂商数值错误码表 | 异常分级靠错误文本规则（显存不足最高级、形状 / 参数类次级），沿用统一层已验证的那套分级，不自建 | 分级粒度粗于昇腾 |
| 设备级真重建 | 压力回收只做进程内回收；设备级故障只上报不自救 | 设备级故障需人工或外层编排介入 |

每条降级都必须**可观测**：`query_capability` 返回当前生效的降级路径与其代价说明。静默降级视为缺陷（`I-10`）。
