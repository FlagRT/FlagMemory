# RUN-GATES —— 测试流程闸门检查表（checker 量尺）

版本：v1.0（2026-10-27）。配套：`PROFILE-PROTOCOL.md`（测量规范 v0.3）。
用途：每两个流程阶段之间，由一个**未参与该阶段产出的独立检查者**对照本文档逐条检查，
全部通过才允许进入下一阶段。检查者不得放水；发现无法通过或指令矛盾时，如实升级说明。

## §0 三条铁律（所有闸门的上位法，违反任何一条=直接不过闸）

1. **输入锚定**：测试对象（模型）、池口径、并发三件输入只从团队真实目标取
   （国产模型：OneRec-8B 先例、Qwen 系备选；池口径=**合理额度梯度轮跑**，
   见 G2——对显存画像有意义的档位都要测，禁无理由缩池单点）。
   目标在机器上不可得 = 停下升级请示，**不得**用"本地可得+能跑通"的替代品。
2. **偏离声明边界**：偏离声明只适用于操作层偏离（腿序、F 取值、判据加严、
   采样方式），**永不**适用于换测试对象或缩小资源口径（池/卡数/并发上限）。
3. **标题即口径**："规范验证跑" = 国产真模型 + 自然池 + PROFILE-PROTOCOL 全流程。
   其他一律命名"移植验收/冒烟/摸底"。文档标题承载口径，不允许标题与实质不符。

## §1 作废数字黑名单（引用即不过闸）

2026-10-27 已撤销的 PPU tiny 跑（Llama-3.2-1B + 256MB 锁池）的以下数字，
**不得在任何新文档中作为 PPU 性能口径引用**：
S1 0.102/0.107/0.14s；S2 decode +1.1%；expand 106.3% 池 +12.4%；
DMA 268 批/3671 块、4 批/36 块。
注：真模型重跑若测出相同数值属新测量，须独立取证、注明本次跑的出处。
两个栈行为观察（flagos triton 按-shape JIT、flaggems device-side assert c5+）
仍然有效，但引用时须注明"待真模型跑重新取证"。

## §2 人闸（只有用户能放行，checker 只验证"人闸确实发生了"）

| 闸 | 放行条件 |
|---|---|
| G0 通道 | 用户明确答复通道（VPN）空闲后，才允许执行任何连接服务器的命令 |
| G-拍板 | 用户对"模型+池口径+并发约束"三件输入明确拍板（确认或修改）后，才允许写 PLAN |

## §3 执行闸

### G1 模型盘点闸
- 候选模型的家族属于国产集合（OneRec/Qwen/GLM/DeepSeek/InternLM/Baichuan 及用户指定者）；
- 每个候选给出：绝对路径、家族与规模、权重完整性（config.json + safetensors/bin 在位）、
  大小 GiB；
- 扫描范围为共享存储的用户目录，扫描过的目录如实列出；
- 无任何国产候选时：不得引入英文/非目标模型顶替，必须升级请示。

### G2 目标锚定闸
- 锚定单三件齐全：模型（优先 OneRec-8B 对齐 P800/910C 先例）、池口径、并发约束
  （含已知 vendor 病态备注）；
- **池口径=合理额度梯度轮跑**（用户 2026-10-27 裁定）：对显存画像有意义的档位
  都要测一遍——至少含两个锚点档：自然池（不锁 kv-cache-memory-bytes，部署真实态）
  与协议/先例锁定档（可比性锚点，如 P800 64GiB=466,032 tok 先例分母）；是否加中间档
  以画像意义为准，每一档在 PLAN 中写明存在理由；B 四档在每档池内独立除法推导。
  禁止无理由的缩池单点；单一档位口径须说明为何其余档位无意义；
- 用户已拍板（G-拍板人闸发生），最终口径以用户决定为准。

### G3 PLAN 预注册闸
- 五要素齐全且与锚定单一致（栈/芯片/模型/冷暖/池口径）；
- 腿本完整：P 池画像 → S1 prefill 三档 → S2 decode → B 四档（池占比除法推导）
  → cost/expand → R 正确性，每腿有**可判定的**有效判据（判定不依赖主观措辞）；
- 暖跑配对、冷 prompt、腿序（轻→重）写入腿本；
- 预期预先写定（跑前），偏离声明（如有）仅限操作层；
- 不引用 §1 黑名单数字；不预先写任何结论性数字。

### G4 部署与池画像闸
- serve 池设置与 PLAN 声明的档位一致：自然池档=不锁 kv-cache-memory-bytes；
  锁定档=协议/先例条款值；如栈默认预留机制存在，如实记录其数值与来源行；
- 每档池的池 tok 数取自引擎日志原文行，并与块常数交叉验证（梯度逐档做池画像）；
- 模型加载成功、诊断打点（DMA/SCHED）在位、卡况（共享/独占）如实记录。

### G5 腿数据闸（每腿单独判定）
- S1：每档每轮冷 prompt（seed 织入）、档内 prompt token 精确等长（JIT 防污染）、
  输出 >1 tok；JIT 离群轮保留并说明；
- S2：max_tokens ≥128 才允许写 decode 结论；暖 1 测 3 取中位+最差；
- B 四档：池占比 25/50/90/110% 由除法推导、每档 ≥2 轮取第 2 轮；expand 档 OFF 侧
  须有 waiting>0 证据；
- ON 侧：DMA 打点计数 >0 且与块数账互洽；OFF 侧：DMA 计数为 0；
- R 正确性：canonical 输出三方（OFF/ON/reference 可用时）逐字全等；
- 任一判据不满足=该腿数据无效，重跑该腿，不得带病进汇总。

### G6 RESULT 溯源闸
- 每个写入文档的数字可溯源到原始 JSON/日志原文（注明文件与字段）；
- 判据逐条给出"过/未过"判定，无"选择性汇报"（未跑/无效的腿如实标注）；
- 标题符合 §0 铁律 3；未引用 §1 黑名单数字；
- 卡已还、服务器状态恢复，如实记录。

### G7 双版本报告闸
- 技术版+通俗版数字完全一致；
- 通俗版五段结构（今天干了什么/测试对象摆清谁哪台哪卡什么栈/数字大白话+表/
  抓出的问题/一句话结论+跨芯对照表）；
- 术语首现带大白话；无未解释的缩写；
- 对外发出前经过 G-过目人闸。

## §4 闸门纪律

- 检查者与产出者不得是同一个上下文；检查者只读，不改文件；
- 修复-重查循环上限 3 轮，仍不过=升级请示，不得放水、不得降低检查标准；
- 检查者发现"闸门本身与事实矛盾/不可能通过"时，停止并如实升级，不得绕过。
