# 设备统一接口张量桥接

## 使用范围与可信边界

`flagmemory.adapters.device_context` 提供可选的 `DeviceContextBridge` 与身份注入协议 `DeviceIdentity`。模块只依赖标准库及本包，导入时不发现设备、不导入框架、不分配设备资源。

桥接实例显式绑定一个设备、一个后端对象和一个默认统一流。调用方必须注入可靠的流身份、当前设备查询、字节水位及事件工厂；缺失、未知身份、错误设备或失败观测均拒绝。后端对象必须按对象身份一致，同名不算同一个后端。设备序号必须为非负严格整数，布尔值不接受。

通用层不证明注入实现的物理事实。生产配置必须有公开源依据及负例，且只能接受它实际核验并强持有的流。主机测试的外部真值表仅是测试依赖，不能作为生产身份配置。普通原生流必须先用设备公开统一 Stream 包装；桥接不猜原生对象形状，不访问 `.device`、`.native` 或私有登记表。

设备的公开 `.native` 可由有证据的具体平台配置作为受审计逃生口使用。规范 key 是受控逻辑对象身份，不保证不同 key 代表不同硬件流。无法合并的受控对象可以保守多留回收屏障；未知外来包装拒绝。

## 构造与张量池

构造签名为：

```python
DeviceContextBridge(
    backend, *, device_index, default_stream, identity,
    make_event, current_device, memory_info_provider,
)
```

- `identity.stream_device(stream)` 返回已核设备整数或未知；`stream_key(stream)` 返回非空、可哈希的稳定 key 或未知。key 只在后端实例和设备身份核验后用于比较，不能充当设备拥有权凭证。
- `current_device()` 是调用方所选公开查询。异常不吞、不补常量；每次设备操作核对绑定设备。调用方在整个池生命周期内保持既有后端、设备和上下文稳定。宿主框架当前设备视图可能有缓存或缺上下文默认分支，不能宣称独立检测外部上下文；具体配置应先拒绝未初始化宿主。
- `memory_info_provider(index)` 必须返回字节单位的 `MemoryInfo(total, used, free)`，均为非负严格整数，`free<=total` 且 `used=total-free`。仅在声明设备内存能力时构造即读一次，后续查询重新读取；查询前后核当前设备。
- `make_event(index)` 是新增注入回调，不是给设备后端现有方法增加设备号。其实现只在已核当前设备上调用公开 `backend.create_event(enable_timing=False)`，再用设备公开 Event 包装。创建时的一致性约束不能证明延迟创建的原生事件已经定域。
- `current_stream(index)` 返回显式默认统一流，不随全局当前流切换自动刷新。

建池使用既有 `create_pool(bridge, device_index=绑定设备, form=PoolForm.TENSOR, base_allocator=allocator, tier_spec=配置)`。底座实现既有 `allocate(nbytes, device_index=0, *, stream)` / `release(base_ref)` 协议。返回对象前必须保证所传原统一流可安全首次消费，并返回可实际读写对象；不能只返回私有映射票据。桥接不自行分配底座、接管张量或重做池账本。

档位由调用方显式提供，主机测试的单档 64 字节只是一项 fixture 配置，不是芯片粒度结论。池的借用登记保护寿命；消费前所需的跨流数据依赖由调用方建立。

## 能力映射

声明在构造时按 `backend.supports(str)->bool` 逐项快照。八项核心能力必须全部满足既有池门禁，缺一项仍拒绝建池。

| 设备声明键 | 池枚举 | 桥接语义 |
|---|---|---|
| memory | DEVICE_MEMORY_INFO | 注入公开字节观测 |
| stream | STREAM | 已核默认流、身份验证和稳定 key 比较 |
| event | EVENT | 新建凭据、显式记录及非阻塞完成查询 |
| bounded_sync | BOUNDED_SYNC | 查询轮询与单调时钟截止预算 |
| graph_capture | GRAPH_CAPTURE | 沿用后端声明，不执行捕获 |
| recovery_probe | PROBE_LEVEL_RECOVERY | 沿用声明，不执行恢复 |
| multidevice | MULTI_DEVICE | 后端能力声明；桥接实例仍只绑定一设备 |
| stream_priority | STREAM_PRIORITY_RANGE | 沿用范围可读声明，不改变优先级 |

其余能力均不声明，即使设备相应键为真。`alloc_handle` 和 `free_handle` 沿既有精确签名抛 `CapabilityNotDeclared(MEMORY_HANDLE, bridge.name)`，不调用下层分配/释放。句柄五字段转换与原字典往返不属于此实现。

没有分配器字节协议、跨流 record_stream、上下文观测、原生真有界同步、上下文生命周期或设备恢复入口。池通过既有借用集对每条相关流各记录事件，等全部完成。归属视图的 `context_ok is None` 保持可见，表示上下文未校验。

## 水位口径

统一设备 `memory_stats()` 的整数 MiB 和静默 fallback 不作为精确字节来源，桥接不调用它，不以 allocator allocated/reserved 推导全局空闲量，也不把缺值补为零。注入公开字节查询失败直接失败。

`used=total-free` 只表示所选公开设备接口的应用可用内存观察值；没有桥接量化损失，不等于瞬间原子全机快照、池硬额度、调度准入保证或池账本。池 in-use/reusable/pending/quarantined 均来自本组件显式接管块的账本。

## 事件、预算与故障

桥接完成凭据强持有所属桥接、目标设备、公开 Event、记录状态与尝试记录的统一流。它不拥有流/事件销毁权。跨桥接事件、不同后端、不同设备及重复记录拒绝；记录调用可能已经产生副作用，因此一次尝试失败后也不能重试同一凭据。

记录前核当前设备与流归属，显式 `public_event.record(已核统一流)`，返回成功且设备后核通过才置已记录。延迟原生事件首次按该显式流定域。未记录或记录不确定时，即使底层 `query()` 会返回 True，桥接也抛 `EventNotRecorded`，不调用底层查询。

`synchronize_event(event, timeout_s)` 以秒为单次预算，要求有限、非负实数且不接受布尔值。零预算只查询一次，不 sleep；正预算共享一个单调时钟截止时间。仅调用公开 `query()`，不调用设备级同步、无界 synchronize 或设备的毫秒 `wait_host(timeout_ms)`，因此没有秒转毫秒的舍入策略，也不声明原生真有界同步。公开查询本身须为非阻塞；桥接不能抢占阻塞的外部回调。

公开方法显式 `NotImplementedError` 转为带具体能力的 `CapabilityNotDeclared`；身份/参数 `ValueError` 转为 `InvalidArgument`，均保留 cause。厂商 `RuntimeError` 等其他故障原样传播。事件故障由既有池屏障转隔离；底座释放失败由池安全托管，不重试不确定释放。无公开解隔离协议时保留可恢复观测状态，不强清托管表。

底座分配器应将明确的公开 OOM 类型按既有池协议转换为 `MemoryError` 并保留 cause；不能把全部 RuntimeError 猜成 OOM。释放交还的是底座引用，不能据此宣称厂商缓存清零或物理释放。

## 主机验证入口与限制

- `tests/interfaces/device_context_fakes.py`：忠实公开调用形状的设备替身、外部真值解析器与同步就绪主机底座，不继承池 FakeBackend。
- `tests/interfaces/test_device_context_bridge.py`：强制依赖、能力缺项、字节值、流归属、事件状态、等待预算、异常传播与真实池跨流生命周期。
- `tests/tools/test_check_layering.py` 与 `tools/check_layering.py`：池不得反向依赖可选适配层。

真实池流程要求 owner 完成而 borrower 未完成仍 pending；全部事件完成才复用同 storage_id，并为新租约产生不同 block_id。旧租约 access/free 拒绝；完整关闭只释放底座一次。故障用例通过公开托管观察/恢复接口验证保留，不直接清生产托管表。

这些是无设备主机合同，不能替代具体平台配置验收、安装后分发检查或新桥接真卡联调。已有其他适配入口的实测不自动归属于本桥接。多设备运行、真实句柄优化、权重/激活/KV 接管、连续模型执行和性能收益均不在本实现的验证范围内。
