# 分级块池与流有序分配：当前实现说明

## 一、导入、建池与受控访问

```python
from flagmemory.pool import create_pool, PoolForm, Purpose, TierSpec

# backend、allocator 由调用方注入；示例档位是测试配置，不是厂商粒度。
pool = create_pool(
    backend, device_index=0, form=PoolForm.TENSOR,
    base_allocator=allocator,
    tier_spec=TierSpec(base_bytes=4096, step_bytes=4096, tier_count=2),
)
lease = pool.alloc_on_stream(4096, purpose=Purpose.SCRATCH)
memory = pool.access_block(lease.block_id)  # 实际可消费底座，不是元数据快照
# 在已登记流提交工作；跨流数据依赖由调用方先建立。
pool.free_block(lease.block_id)
# 此后不得继续通过 memory 或其他 Python 别名读写、排入工作。
pool.drain_stream(timeout_s=0)  # 只观察；未完成时继续保留待回收
report = pool.destroy_pool()
```

底座以 `storage_id` 标识，当前租约以 `block_id` 标识，每次复用签发新租约；归还或隔离立即失效。`access_block` 返回当前在用租约的可消费对象，`block_view` 返回快照。跨池/重复/过期凭据报 `OwnershipViolation` 且不改变当前块。池无法撤销任意 Python 别名，调用方必须归还前提交工作并登记全部相关流，归还后停止使用旧别名。

关闭有未决资源时保持可恢复，禁止新增分配/登记/声明/访问，允许已有租约归还、排空和重试关闭；在用块通过 `LeakDetected.report` 给出清单。`DestroyReport` 同时包含 pending、leaked、quarantined、closing、completed、custody_id。进程级强托管保持底座、后端、分配器、流与已有事件；`list_custodied_pools` 查各状态数量和字节数，`recover_custodied_pool` 找回池。全部安全完成才销毁并注销，隔离无安全证明则保留到进程退出。开放且无隔离的池仍由调用方显式关闭，不以丢弃变量替代。

## 二、张量路径与首次流就绪

当前 `native_stream_ordered=False`，使用组内空闲链、流登记及事件屏障。首次芯片验证限定 `PoolForm.TENSOR`，底座实现 `allocate(nbytes, device_index=0, *, stream)`：在指定目标流分配，或返回前建立首次使用就绪依赖；同步底座可保证已就绪。返回可被调用方直接消费或经公开适配接口读写的对象，私有映射票据不足以满足契约。

后端以 `validate_stream_device(stream, device_index)` 明确核流设备；事件按池设备号创建，不猜测流对象属性。跨流声明只保护回收寿命，数据先后依赖仍由调用方建立。缺上下文观测时返回 `context_ok=None` 及降级说明。

一次排空/关闭的全部块共享单调钟截止时间；有限非负等待值才合法，布尔、负数、NaN 与无穷拒绝。零等待仅观察，正等待到期可恢复，不按次数隔离。后端单次事件 query 必须非阻塞；公共预算不抢占任意后端调用或底座 release。

## 三、档位来源

`TierSpec` 显式配置优先，`TierTable.source=caller_config`；未配置时由满足 `GranularitySource` 的后端查询最小/推荐粒度，来源为 `backend_query`。推荐值作基数、最小值作对齐步长，两种来源都缺则报错，不编字节常数。手工测试配置不能标成厂商实际粒度；昆仑芯粒度基数仍须实测或厂商确认。

当前查询中的 `pool_in_use`、`pool_reusable`、`pool_pending`、`pool_quarantined` 来自本组件显式接管块的账本；文中沿用的「引擎侧」在当前实现里仅指这组池内统计，不是已接入 vLLM 的全局 KV 指标，也不表示自动接管框架全部分配。设备侧三键来自后端设备查询，范围与本池账本不同；历史 vLLM 画像是设计输入，不能充抵当前组件的运行覆盖。`engine_fragmentation` 当前为本池可复用字节除以本池持有字节，非全局引擎碎片率。

## 四、当前限制

- 建池可登记换出回调（`offload_callback`）：登记后 `reclaim(allow_tier_offload=True)` 先调回调一次并把回报字节数计入 `ReclaimResult.tier_offloaded_bytes`，未登记仍抛 `NotWired`。通用分层管理器（回调的消费方）尚未实现。
- 现有三套卸载适配器尚未接入池，不据它们的既有实测宣称池已通过。OneRec-8B 已有受控单输入缓冲消费实例；它不是权重、激活、KV cache 或生产业务的全面接入。
- 原生流有序优化、真实句柄和跨进程路径不属于首次芯片验证。SDK 声明/符号调查、后端声明和运行验证分开核对；原语补探见指挥台仓 `flag_RT/inbox/调研-四芯片SDK显存原语面补探-20261103.md`。
- 池接口限单线程调用，不提供后台回收、析构设备操作或隔离强制释放。接口语言面已定稿（ADR-0015，2026-11-05）：类型存根 + 接口文档，C 头触发式；当前未触发，无 C ABI。

## 五、主机、真卡入口与证据

[主机测试入口](../../tests/README.md) 覆盖池、能力层和 [接口签名检查](../../tests/interfaces/test_stub_matches_impl.py)。主机假后端验证实际可消费对象与流就绪协议，不能证明厂商运行语义。

旧 [CUDA 兼容池测试](../../tests/pool/test_pool_realcard.py) 尚未适配当前接口和租约断言，含按空闲显存倍数申请的用例，**不要直接执行全部 realcard**。独立候选适配器与测试入口已有昇腾 910C 单芯片受控验证实例，覆盖映射、4096 字节读写健康、三个生命周期用例及 OneRec-8B 的单输入缓冲消费与数值对照；固定环境和证据范围见 [验证实例记录](../validation/2026-11-04-ascend-pool-onerec.md)。这不认证驱动绝对隔离，也不代表任意配置或生产多平台均通过；新的设备执行仍须核定目标、窗口与资源范围。须显式选择独立测试文件、遵守资源上限，未覆盖不算通过；入口与启用条件见 [测试说明](../../tests/README.md)。

旧取证逻辑默认打印，指定 `FLAGMEMORY_REALCARD_EVIDENCE` 才写文件，调用方须选仓外路径；代码不自动检查该路径。`reports/` 历史证据尚未迁移完，保持原样；探针脚本随包提供，不作为稳定模块 API。设计见 [池设计](../design/显存池概念与设计基础.md) 与 [分层设计](../design/分层存储概念与设计基础.md)，现行契约见 [接口文档](../../flagmemory/interfaces/接口文档-显存池对外接口.md)。

设备统一接口的可选张量桥接、昇腾绑定的启用条件及未验证边界见 `docs/impl/设备统一接口张量桥接.md`。
