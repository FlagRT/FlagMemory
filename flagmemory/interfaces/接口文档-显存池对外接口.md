## 一、怎么拿到一个池

```python
from flagmemory.pool import create_pool, PoolForm, Purpose, TierSpec, WorkloadType

pool = create_pool(
    backend,                       # 设备方向统一后端接口的实现（满足 caps.DeviceBackend）
    device_index=0,
    form=PoolForm.AUTO,            # 自动 / 强制张量级 / 强制句柄形态
    workload=WorkloadType.GENERATIVE,   # 向量化 / 生成式 / 混合，预算仲裁要用（I-7）
    base_allocator=my_allocator,   # 张量级形态的底座；句柄形态可不给
    tier_spec=TierSpec(base_bytes=..., step_bytes=...),  # 后端查不到粒度时必须给
)
```

三件必须知道的事：

1. **池不建设备上下文**（`I-4`）。调用方必须已经处在目标设备的上下文里 —— 昆仑芯平台只允许
   一个上下文，第二次创建直接失败，抢建会让框架起不来。
2. **形态在建池时一次定下，不在单次分配里偷换**。强制了某个形态而后端没有对应能力，
   建池直接报错，不静默退化（`I-10`）。
3. **档位粒度不写死常数**。后端有分配粒度查询就按它推导（昇腾 / 寒武纪 / 平头哥 三家各有
   「最小 / 推荐」两档）；**昆仑芯 P800 两边都查不到**，那一家必须由调用方把实测得到的粒度
   用 `tier_spec` 喂进来，否则建池报错。

### 两种实现形态

| 形态 | 适用 | 底座 |
|---|---|---|
| **张量级（默认，四家通用）** | 四家全部 | 调用方注入的 `BaseAllocator`（取空张量作底座）。池本体不许 import 框架，所以这一层由外面注入 |
| 句柄形态（优化路径） | 声明了统一内存句柄能力的三家 | 后端的句柄申请 / 释放 |

两种形态**对上层暴露同一套接口**，差异只在能力层内部分支。

### 流有序分配的两条路

池的对外语义是「**按流分配 + 后端能力标记**」。`query_capability().native_stream_ordered`
就是那个标记：

- **标记为假 ⇒ 自管路**（基线，无条件可用）：池自己记流序、按档维护空闲链、用事件适配器做
  回收屏障。昆仑芯 P800 无条件走这条；装了较老 CANN 大版本的昇腾机器也走这条。
- **标记为真 ⇒ 原生路**（优化路径）：后端实现 `StreamOrderedAllocator` 协议时，取块与还块包
  到原生原语上。

**两条路的对外行为相同**，调用方不需要分支。自管路的回收策略按三家原生池属性的三个旋钮设计
（见下文 `ReusePolicy`），便于两条路对齐着调。

## 二、15 条操作

### 2.1 一览

| # | 操作 | 一句话 |
|---|---|---|
| 1 | `create_pool` | 在既有设备上下文内建池，定下形态与档位表 |
| 2 | `destroy_pool` | 排空待回收、交回全部块、放开流强引用，给出隔离与泄漏清单 |
| 3 | `alloc_on_stream` | 按流分配一块：定档、复用或取新块，绑定所属流与用途标签 |
| 4 | `free_block` | 归还一块：进待回收并取屏障凭据 |
| 5 | `register_stream` | 把一条流登记进池并强持有 |
| 6 | `declare_cross_stream_use` | 声明一块将被另一条流读写 |
| 7 | `drain_stream` | 推进待回收队列，把已确认完成的块转可复用 |
| 8 | `query_watermark` | 水位，双指标同时返回 |
| 9 | `query_fragmentation` | 碎片，双指标 + 各档空闲分布 |
| 10 | `compact` | 碎片整理 |
| 11 | `reclaim` | 压力回收 |
| 12 | `verify_block_ownership` | 块归属校验 |
| 13 | `query_budget` | 预算视图 |
| 14 | `query_capability` | 能力与降级态 |
| 15 | `query_audit` | 审计视图 |

### 2.2 逐条契约

形参与返回类型以 `pool.pyi` 为准（单测核对二者一致，这条进持续集成）。下表给的是**语义与
失败行为**。

#### 1 `create_pool`

| | |
|---|---|
| 返回 | 池对象，其 `form` / `native_stream_ordered` / `tier_table` 给出生效的形态、能力标记与档位表 |
| 报错 | L0 核心能力不齐 ⇒ 这款芯片不支持池，池不起（`I-8`）；强制句柄形态而后端未声明该能力 ⇒ 报错，不静默退化（`I-10`）；强制张量级而没注入底座 ⇒ 报错；粒度两条来源都没有 ⇒ 报错，不编默认值 |

#### 2 `destroy_pool`

| | |
|---|---|
| 返回 | 已交回字节数与块数、隔离清单、泄漏清单、排空是否超时 |
| 报错 | 还有 `在用` 块 ⇒ 抛 `LeakDetected`，泄漏清单在异常的 `.report` 上。**池不静默释放在用块**（下面可能还在跑） |
| 注意 | 排空超时按可恢复态上报（`drain_timed_out`），不是失败（`I-11`） |

#### 3 `alloc_on_stream`

| | |
|---|---|
| 入参 | 字节数；流标识（缺省 = 默认流）；用途标签（缺省 = 未声明） |
| 返回 | 块快照：块标识、状态（`在用`）、档位与实际字节数、所属流、用途标签 |
| 报错 | 容量不足 ⇒ `CapacityExhausted`，错误里带双指标水位与该档空闲量；字节数非正、标签不在枚举内、流未登记 ⇒ `InvalidArgument`；请求超过最大档 ⇒ 定档失败即报错 |
| 不做 | **不自动缩小请求、不自动换档、不自动阻塞等待**（`I-10`）；不自建上下文；不调整流优先级 |

#### 4 `free_block`

| | |
|---|---|
| 返回 | 块的新状态 = `待回收` |
| 报错 | 非本池块 / 重复归还 / 归属不符 ⇒ `OwnershipViolation`，**块转隔离** |
| 注意 | **归还不等于可复用。** 调用方看到的「还回去了」只到 `待回收`；流序未确认时池绝不把块交给下一个人。要让它变成可复用，调 `drain_stream`（或靠下一次分配的机会性推进）。 |
| 为什么不等厂商报 | `I-1`：二次释放的厂商行为四家相反 —— 昇腾的裸释放**静默返回成功**，昆仑芯的缓存分配器删除**如实报错**。指望厂商报，在一家上会完全失效，所以拦截一律由池自己的账本完成 |

#### 5 `register_stream`

| | |
|---|---|
| 返回 | 池内流标识。同一条流重复登记返回同一标识 |
| 注意 | **池对该流转为强引用并保持到池销毁**（`I-3`）。流 + 弱引用 + 被回收在平头哥与昇腾上是进程退出期段错误，所以池不做任何基于弱引用的自动清理 |

#### 6 `declare_cross_stream_use`

| | |
|---|---|
| 返回 | 更新后的跨流借用集 |
| 报错 | 块不在 `在用` / 流未登记 ⇒ `InvalidArgument` |
| 两条路径 | 后端声明了跨流内存保护能力 ⇒ 同时经统一层登记；未声明（寒武纪 MLU590）⇒ 只记池内借用集并上报降级态。**对外语义完全相同**，差别只在池内部的屏障成本与回收延迟 |
| 边界 | **池不承诺在未声明跨流使用的情况下保护跨流读写。** 未声明就跨流使用属调用方错误 —— 这一条在两条路径下都成立，不随芯片变化 |

#### 7 `drain_stream`

| | |
|---|---|
| 入参 | 流标识（缺省 = 全部）；超时 |
| 返回 | 本次离开待回收的块数与字节数、仍在待回收的深度、超时块清单、转隔离块清单、是否可恢复超时 |
| 注意 | **超时不等于失败**（`I-11`）：块留在 `待回收`，按可恢复态上报；只有累计超时越过阈值才转隔离。整个过程**只轮询事件，不做阻塞等待** —— 四家里只有昇腾是真有界同步 |

#### 8 `query_watermark`

| | |
|---|---|
| 返回 | 设备侧三键（总量 / 已用 / 空闲）+ 引擎侧四项（在用 / 可复用 / 待回收 / 隔离），**两侧都给** |
| 报错 | 设备侧三键查询不可用 ⇒ 报错，**不用引擎侧单边数充抵** |
| 为什么 | `I-6`：框架预分配会把设备侧读数压成恒平（实例：某次实测中设备侧波动仅 142 MiB），块的真实涨落只在引擎侧可见。只看设备侧会误判成「池没有动态」或「存在泄漏」；只看引擎侧则看不到池外部的占用 |

#### 9 `query_fragmentation`

| | |
|---|---|
| 返回 | 双指标水位 + 各档空闲块分布 + 本池**可立刻满足**的最大单块 + 两侧碎片率 |
| 注意 | 「可立刻满足的最大单块」取自空闲表命中，**不是地址空间连续量** —— 池不持有地址空间（`I-9`），给不出连续量这个数就不假装给 |

#### 10 `compact`

| | |
|---|---|
| 入参 | 目标档位（缺省 = 全档）；是否允许交回底座 |
| 返回 | 整理前后双指标读数、交回字节数与块数、是否有改善、一句说明 |
| 注意 | `在用` 与 `待回收` 一概不动。无改善**如实返回「无改善」**，不把空操作报成成功（`I-10`） |
| 这一层做不到的事 | **合并做不到。** 合并要求池能动地址空间，而池不持有地址空间、也不假设拿到裸内存（`I-9`）。所以整理动作只有「交回底座」一种 —— 这是现状，不是待优化项 |
| 价值场景 | 碎片整理的价值在**生成式与混合负载**。向量化负载的池是整块分配、本来无碎片，所以这类负载上不承诺收益 |

#### 11 `reclaim`

| | |
|---|---|
| 入参 | 目标释放量**或**压力等级（必须给且只给一个）；是否允许触发分层换出 |
| 返回 | 实际释放量与块数、是否达到目标、按标签聚合的释放量、一句说明 |
| 注意 | 只动 `可复用` 的块，按用途标签次序走：临时工作区 → 激活 → KV 缓存。**权重、通信缓冲、未声明一概不动**（`I-12`）。达不到目标量就返回实际量并标「未达目标」，不谎报 |
| 不做 | **不做任何设备级恢复**（`I-5`）：四家里只有昇腾有设备级真重建，另三家分别是无原语、确认不具备、以及原语返回成功但设备随后全废 —— 自救路径在三家上跑不通 |
| 尚未接线 | `allow_tier_offload=True` 当前**报错**（分层换出的联动属分层存储那条出口）。按「不给空壳」的纪律报错而不是返回假成功，详见交付说明的未实现清单 |

#### 12 `verify_block_ownership`

| | |
|---|---|
| 返回 | 设备 / 上下文 / 账本**三项分别给**，外加生效的降级说明 |
| 注意 | 缺上下文只读观测能力（寒武纪 MLU590）时，上下文那一项是「未校验」而**不是「通过」**，并且必然附一条降级说明。调用方据此知道这次放行的校验强度低于别家 |
| 为什么主动查 | `I-1`：主动查，不等厂商报 |

#### 13 `query_budget`

| | |
|---|---|
| 入参 | （可选）按用途标签筛选 |
| 返回 | 按标签聚合的已分配量 + 双指标水位 + 可压余量**与其判读文本** + 聚合量来源 |
| 为什么给文本不给裸数字 | `I-7`：同一个「显存利用率」参数在两类负载下语义不同 —— 向量化服务的池是**纯余量**（可压），生成式服务的池是**真实并发容量**（压了就掉并发，实例：该参数由高压到低，并发能力相差数倍）。**只看水位数字不看负载类型的仲裁一律视为缺陷**，所以这个口把数字与判读绑在一起给 |

#### 14 `query_capability`

| | |
|---|---|
| 返回 | 后端名、实现形态、原生流有序标记、L0 是否齐备、缺的 L0 能力、启用的能力分支、**生效的降级路径与各自代价**、档位粒度来源 |
| 注意 | 这个口**恒可用**，是降级可观测性的基础。静默降级视为缺陷（`I-10`），所以每条降级都带「改走什么」与「代价是什么」两句话 |

#### 15 `query_audit`

| | |
|---|---|
| 返回 | 在世块数、待回收深度、隔离量与隔离原因分布、分配请求数、复用命中数、向底座取块次数、复用命中率 |
| 注意 | 隔离是终态：不复用、不释放、只上报。池宁可泄漏一块、把问题暴露出来，也不把一块状态不明的显存再交给别人。隔离量是对外可查的审计指标 |

## 三、用途标签

标签六类，**可增不可改语义**。标签落在句柄 / 请求上而不是池内部，原因是**通信缓冲那一类由
别的方向申请** —— 池只有从标签上看到它，才知道「这块别动」。

| 标签 | 含义 | 池的处理 |
|---|---|---|
| 权重 | 模型参数，整个服务生命周期常驻 | 永不回收、不进复用池，只记账（`I-12`） |
| KV 缓存 | 推理上下文缓存 | 可复用、可分页、可降级到主机侧（分层存储的主对象） |
| 激活 | 前向 / 反向中间结果 | 短生命周期，优先复用，块复用的主战场 |
| 通信缓冲 | 集合通信的收发缓冲 | **不得被池回收**，只记账（`I-12`） |
| 临时工作区 | 算子工作空间 | 最优先回收 |
| 未声明 | 申请方没给 | 最保守：不回收、不复用（`I-12`） |

压力回收的候选次序：**临时工作区 → 激活 → KV 缓存**。另外三类不在候选里。

> 内存句柄上新增「用途标签」与「所属流」两个字段这件事，是与设备执行上下文方向**联合冻结**
> 的内容（设计文档 4.3），不由显存方向单方决定。冻结前池按「可选、缺则按最保守处理」工作。

## 四、块的六个状态

| 状态 | 含义 | 块在哪 |
|---|---|---|
| `申请中` | 池已受理一次分配请求，正在定档、找可复用块或向底座取新块 | 调用方看不见 |
| `在用` | 已交给调用方，归属某条流 | 调用方手里 |
| `待回收` | 调用方已归还，但相关流上的操作未确认完成 | 池的待回收队列 |
| `可复用` | 流序屏障已确认完成，块回到对应档位的空闲表 | 池的分级空闲表 |
| `已归还` | 块被交回底座，块对象终结 | 不存在 |
| `隔离` | 账本与实际不符、归属校验失败、或屏障超时超阈 | 池的隔离区，**不复用、不释放、只上报** |

两条调用方要记住的：

- **归还（`在用`→`待回收`）与可复用（`待回收`→`可复用`）是两件事。**
- **`隔离` 是终态**，不自动迁出，只能人工介入或进程结束处置。

块标识**生命周期内不复用** —— 已归还的标识不再分配给新块，于是审计对账时「这个标识指的是
哪一块」永不含糊。

## 五、回收策略的三个旋钮

`ReusePolicy` 的三个旋钮与三家原生流有序池的属性同形（按事件依赖复用 / 机会性复用 /
释放阈值），便于自管路与原生路行为对齐。

| 旋钮 | 自管路里的含义 | 缺省 |
|---|---|---|
| `follow_event_dependencies` | 块的放行以事件依赖为准：屏障确认了所属流与跨流借用集上的操作才转可复用。**固定开启，不提供关闭** —— 关掉等于把「待回收」的块当「可复用」交给下一个人 | `True`（给 `False` 直接报错） |
| `opportunistic` | 该档空闲表为空时，先顺手推进一次待回收队列再决定是否向底座取块 | `True` |
| `release_threshold_bytes` | 池保留的可复用字节上限；归还路径上超过阈值的部分直接交回底座，不留在空闲表 | `None`（不设阈值） |

## 六、异常一览

| 异常 | 什么时候 |
|---|---|
| `InvalidArgument` | 字节数非正、标签不在枚举内、流未登记、入参互斥条件不满足 |
| `CapacityExhausted` | 容量不足。错误里带双指标水位与该档空闲量 |
| `TierResolutionError` | 档位表推导不出来（两条粒度来源都没有），或请求定不进任何档 |
| `OwnershipViolation` | 非本池块 / 重复归还 / 归属不符。相关块转隔离 |
| `LedgerInconsistent` | 账本与底座不符。相关块转隔离并上报，不继续动块 |
| `BlockQuarantined` | 对隔离区里的块做了操作 |
| `FormUnavailable` | 强制了某形态而后端未声明对应能力。**不静默退化** |
| `NotWired` | 这条路在当前实现里没有接线。存在的意义是**不给空壳** |
| `LeakDetected` | 销毁时还有 `在用` 块。泄漏清单在 `.report` |
| `PoolError` | 以上各类的基类；另用于设备侧查询不可用、底座释放报错等 |

总纪律一句话：**失败就报错，不静默退化**（`I-10`）。池可以降级（走降级路径并上报降级态），
不可以悄悄给出一个不满足请求语义的结果。
